# P-01: split `harness-cli/src/lib.rs` into modules

Done on branch `P-01` (worktree `.wt-w-P-01`), 2026-10-01.

## What changed

`crates/harness-cli/src/lib.rs` (1350 lines) is now a root that keeps only
the crate docs, the lints, the `note!`/`say!` macros (textually in scope in
every module below), the public `Cx` struct and the re-exports:

- `args.rs` — `USAGE` and the `--key value` parser (`options`).
- `inputs.rs` — the task/policy/profile readers: `TaskFile`,
  `BudgetFile`, `PolicyFile`, `ExecFile`/`ProgramFile`/`LimitsFile`,
  `PresubmitFile`, `read_input`, `strict`, `Inputs`, `required`, `inputs`,
  `run_config`, `builtin_registry`, the `BUDGET_MAX_*`/`INPUT_MAX_BYTES`
  consts.
- `approver.rs` — `ApproverSource`, `TerminalApprover` (public, re-exported).
- `report.rs` — the gate-child ending: `exit` codes, `Outcome`, `info`,
  `refused`, `emit`.
- `cmd_run.rs` — `run`/`resume`: `run_or_resume`, `try_run`,
  `from_refusal`, `presubmit_in_words`, `possibly_environmental`,
  `outcome_in_words`, `harness_journal_cause`; the
  `a_pressed_step_is_an_info_finding_and_no_step_is_none` unit test moved
  here with the code.
- `cmd_replay.rs` — `replay`, `try_replay`, `REPLAY_SCOPE(_SHORT)`.
- `cmd_profile.rs` — `profile_check`.
- `cmd_manifest.rs` — `manifest_check`.
- `dispatch.rs` — `main_with` (public, re-exported), `Verb`, `gate_child`,
  `DEFAULT_GATE`.

Public API unchanged: `Cx`, `main_with`, `ApproverSource`,
`TerminalApprover` all resolve at their old paths (`harness_cli::…`);
`main.rs` and the tests are untouched.

## Tests

- All existing `cargo test -p harness-cli` pass unchanged: `tests/cli.rs`
  (23), `tests/exit_h1.rs` (2, `#[ignore]`d as before).
- Added `tests/public_api.rs::cli_public_api_unchanged`: compile-only use
  of `Cx`, `main_with`, `ApproverSource`, `TerminalApprover` from outside
  the crate.
- Added `args.rs::usage_text_unchanged`: golden of `USAGE`.

## Notes for the manager / later slices

- `Cx::note`/`Cx::say` are now `pub(crate)` (they were private); nothing
  new is public.
- `note!`/`say!` stayed `macro_rules!` at the crate root, declared before
  the `mod` lines so their textual scope covers every module; no
  `#[macro_use]` needed.
- Cross-module items are `pub(crate)`, so H-A slices (new verbs) add a
  `cmd_*.rs` and one match line in `dispatch.rs`, as the hotspot note
  prescribes.
- `tests/public_api.rs` constructs `TerminalApprover` (its `new` cannot be
  taken as an `fn` pointer: two higher-ranked lifetimes in the return type
  are not coercible). Constructing it starts its stdin-reader thread, which
  nobody asks and which dies with the test process.
