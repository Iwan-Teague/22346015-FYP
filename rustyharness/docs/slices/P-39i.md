# P-39i — research sessions without a workspace (skeleton, no web yet)

## What

A task spec can now name its session kind (`TaskSpec.kind`:
`harness_policy::SessionKind`, `Coding` by default). A `Research` spec is
driven by `run_research` (a new public entry in `harness-run`), which runs
the P-13 session loop with **no workspace**: no tree walk, the no-workspace
facts (zero files, the digest of an empty walk) in the header and in every
`UserTurn`, the research context format `rh-research/1`, and the header's
new `session_kind` / `web` keys (INV-42: the session's own authority,
journaled before any use).

`prepare` and `plan` take the workspace as `Option<&Path>`. `Prepared`'s
read/edit/patch tools and its tree are `Option`s; a research branch
refuses, fail closed, an exec section, pre-submit commands, protected
paths, a workspace, web capability grants (P-39j wires the driver side of
the web tools), and the coding registry — and demands a confinement whose
`require()` succeeds (no unconfined fallback, INV-42).

## Design calls

- **`rh-research/1` is its own format line.** The `rh-context` lines (5
  batch, 6 session) are byte-identical to before; coding journals audit
  exactly as they did. `FactValue` gained a `Text` variant (research
  facts are settled, not measured) and lost `Copy` — no behaviour change.
- **The airlock witness demand is armed but unreachable.** §5.3/INV-46:
  a session that may FETCH demands `covers(AIRLOCK_CASES)`. This slice
  grants no web capability (`check_research_spec` refuses
  `harness.web.fetch`/`harness.web.search` outright, and no committed
  matrix row covers the proxy cases — they arrive with P-39j's spawn
  path), so `prepare` demands a real, successful `require()` witness for
  every research session and applies the `covers` demand on web grants,
  where it goes live. Fail closed either way: no witness, no session.
- **The `web` header key is a digest**, not a structure: `Trusted::Text`
  is `&'static str` only, and the allowlist is run input. `web =
  sha256(canonical JSON {allowlist, confirmed, search})`, computed by
  `header::web_grant_digest`, recomputed by the audit and resume paths
  (`compare::expected_inputs`).
- **The P-29 ask floor is coding-only**: a research session has no edit
  tools, so `plan` skips `protected_policy` for it.
- **Resume** (`resume_session`) reopens a research session with
  `workspace: None`; the turn-start tree check and the mid-turn tree
  check are skipped when there is no workspace (nothing to measure,
  P-05 D4 is a coding session's check). `resume` (batch) refuses a
  research spec by name.
- The audit reuses `audit_session`: the replay passes `research: true`
  to the loop, which renders `build_research` from the recorded turn
  facts (the no-workspace facts are present in the journal, so the feed
  path is untouched).

## Tests

`crates/harness-run/tests/research.rs` (the card's eight, plus a
turn-limits check):

- `research_session_has_no_workspace_grant`
- `research_session_runs_two_turns_and_audits_clean`
- `research_header_records_kind_allowlist_and_confirmation`
- `coding_header_digest_unchanged`
- `batch_and_session_context_digests_unchanged`
- `research_context_format_is_rh_research_1`
- `research_refused_without_conformed`
- `resume_of_research_session_skips_tree_check`
- `research_session_turn_limits_checked`

## Not in this slice

Web fetch/search tool wiring (P-39j), the fetch budget line in the
research facts (budgets are not in `WebGrant` yet), CLI verbs/flags for
research tasks (P-39k): the CLI's specs are `Coding` by construction.
