# P-38b: budget carve and child spend in the meter (slice note)

Card: docs/slices/P-38-subagents.md §"P-38b"; design note §5 (and §4 for why
wall never refuses). Crates: harness-core, scripts/ci (purity.sh only).

## What was added

`crates/harness-core/src/lib.rs` (the Meter's home; the note's §18 first
option, so the purity gate's owner exemption for `ChildSpend::recorded` is
the existing lib.rs one and no new file needs reviewing):

- `Carve { steps, tokens, wall }` and `CarveRefused::{Steps, Tokens}` (each
  carrying `have`/`need`), constants `CHILD_STEPS_DEFAULT = 15`,
  `CHILD_STEPS_MIN = 3`, `CHILD_TOKENS_MAX = 200_000`,
  `CHILD_WALL_MAX = 600 s`, and the pure `carve(steps_left, tokens_left,
  wall_left, min_tokens)` exactly as the note's §5.1 pseudocode: steps
  `min(15, (steps_left - 1) / 2)` refusing below 3, tokens
  `min(200_000, tokens_left / 2)` refusing below `min_tokens`, wall
  `min(600 s, wall_left / 2)` never refusing. Steps are checked before
  tokens (the note's admission order). Saturation everywhere; no panics.
- `ChildSpend` with private fields and getters (`steps`, `tokens`,
  `estimated`, `wall`); `measured(&Meter)` reads a child meter (the only
  constructor a live run uses); `recorded(..)` is the journal re-feed
  constructor for audit/resume.
- `Meter::absorb_child(&ChildSpend)`: refuses on an existing latch, adds
  steps (saturating, latching `Budget(Steps)` when the limit is passed),
  adds tokens (sticky `tokens_were_estimated` from the child's flag),
  derives cost from THIS meter's pricing (never asserted), adds wall, then
  the same renewal check as `record_tokens` (tokens → wall → cost).

`scripts/ci/purity.sh` (section 2c, beside the `Meter::new(_resumed)?`
scan): `ChildSpend::recorded` may be named in code only by its owner
(harness-core/src/lib.rs), `crates/harness-run/src/driver.rs`,
`crates/harness-run/src/driver/*` and `crates/harness-run/src/replay/*` —
the note's "driver and replay", matching where the live absorb (measured)
and the re-feed (recorded) happen.

`scripts/ci/purity-selftest.sh`: the card's case
`child_spend_recorded_outside_driver_refused`, planting a call in another
crate, in `crates/harness-run/tests/`, and in run-crate source outside the
exemption (`session.rs`); all three must be refused with the new reason.

## Decisions taken fail-closed (unattended)

- Everything lives in `lib.rs`, not a new `delegate.rs` module: the note
  allows either; lib.rs keeps the reviewed purity exemptions valid without
  editing them again, and matches where the Meter already lives.
- `CarveRefused` is a new public typed error (the card does not name one);
  it carries the measured `have`/`need` so the admission refusal text of a
  later slice can quote numbers without recomputation. Display included.
- `ChildSpend` fields are private with getters, mirroring `Meter`
  ("spend is never asserted by a caller"): `recorded` takes the values,
  but only the gate-exempt driver/replay code may call it, and journal
  writing in a later slice reads through getters.
- `absorb_child` refuses when the meter is already latched (same as
  `charge_step`/`record_tokens`/`tick_wall`), so a resumed/audit replay
  that re-absorbs cannot double-charge a stopped run.
- `crates/harness-run/src/replay.rs` (the module hub) is NOT exempt — only
  the `replay/` files are. A later slice needing it there extends the gate
  by review; likewise tests calling `recorded` must live under `driver/`
  or `replay/` modules (e.g. `#[cfg(test)]` in those files), since
  `crates/harness-run/tests/` and `src/tests.rs` are refused.

## Not done here (later slices, by design)

No loop code, no journal record, no audit rule: admission, the child run,
`ChildRun`, and the re-feed belong to P-38d/e/f. This slice is pure and
adds no dependency, no `rh-context` bump, no pinned-digest change.
