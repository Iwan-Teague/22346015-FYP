# P-06: incremental SSE streaming observer (slice notes)

Status: implemented on branch `w/P-06` (verify `git log`). Crates touched:
`harness-model-core/src/wire.rs`, `harness-model/src/{http.rs,client.rs}`, new test
`harness-model/tests/stream_mock.rs`. No new dependencies. No design-doc or README change.

## What was built

- `wire.rs`: `pub trait StreamObserver { on_text(&str), on_reasoning(&str), on_tool_call_name(&str) }`
  and `pub struct SseReader<'o>` — the incremental reader behind `parse_sse_reply`, which is now a
  wrapper (`new(None)` + `feed(body)` + `finish`). Grammar identical to the old whole-body parse:
  `data:` lines joined with `\n` per event, blank line flushes, `:`/`event:`/`id:`/`retry:` ignored,
  `data: [DONE]` ends, anything after `[DONE]` refused, non-SSE line refused. Strictness preserved:
  each newline-terminated line is UTF-8-decoded on its own (a `\n` byte can never appear inside a
  multi-byte character), so a split anywhere — including mid-character — is safe and invalid UTF-8 is
  still refused with the same error.
- Observer semantics: deltas only, in stream order, `&self` methods (an observer keeps its own
  `RefCell`/`Mutex`, like `ServerClaims`). `reasoning_content` is read strictly (non-string ⇒
  `Unusable`) but **never accumulated** — observer only — so the `Completion` is byte-identical with
  and without an observer (test: `reasoning_deltas_go_to_the_observer_only`). `on_tool_call_name`
  receives each name fragment as it streams (in practice one piece; arguments are not surfaced).
- `http.rs`: `exchange` takes `on_chunk: Option<&mut OnChunk>` (`dyn FnMut(&[u8]) -> Result<(), HttpError>`).
  It is invoked only for a **200 + `Content-Type: text/event-stream`** reply; every other status and
  content type is collected whole exactly as before, so the client's retry logic can never see a
  partial body. Emission points: per contiguous piece after each fill (`Close` framing, including the
  bytes that arrived with the head — the sink's first piece), per chunk payload (`chunked`), per
  contiguous piece (`Content-Length`). A sink error aborts the exchange at once (fail closed: a
  broken stream is not read to the end). Deadline, read timeout and both size caps bind exactly as
  before; every cap check still runs before the bytes are accepted.
- `client.rs`: `OpenAiCompatible::with_observer(Box<dyn StreamObserver + Send>)` (builder, `#[must_use]`).
  The stored box is `+ Send` so the client stays `Send` (backends move; callbacks run on whichever
  thread calls `complete`). `attempt` feeds an `SseReader` through the sink while `exchange` still
  collects the body; a `200` event stream is finished through the reader (same `Completion` the
  one-shot parse builds), a parse error aborts the read and is returned in place of the transport
  error; `application/json` and non-200 paths unchanged. `Debug` is now manual and prints only
  whether an observer is set (never its contents, matching the `ApiKey` rule).

## Deliberate readings of the brief (fail-closed, simplest)

- **Sink restricted to 200 + `text/event-stream`** in `exchange` (not in the client): the client
  cannot know the content type before the head is parsed, and feeding a JSON reply to the SSE reader
  would either buffer it whole or misparse it. Non-streaming replies and every retryable status are
  byte-for-byte on today's path (existing `client_mock.rs` untouched and green).
- **`on_tool_call_name` gets fragments, not a completed name.** Delivering the whole name would need
  deferral logic (names can span chunks); fragments match `on_text`/`on_reasoning` semantics. Usually
  servers send the name in one piece.
- **No journal, replay or context change.** The brief: the returned `Completion` is assembled exactly
  as today and is what is journaled; the observer is not on the trait, so the loop and replay are
  untouched — no new record, no recompute rule, no `context_format` bump (nothing rendered to the
  model changes; the request bytes are identical, pinned by `observer_never_affects_request_digest`).
  Per roadmap §4.1 this is a loop-invisible feel feature, not a loop-visible one.

## Tests

New file `crates/harness-model/tests/stream_mock.rs` (mock TCP server sending pieces with delays;
`client_mock.rs` unchanged):
`stream_observer_sees_text_before_reply_completes` (observer sees the first delta while the mock is
still holding the rest back, before `complete` returns), `stream_result_equals_nonstream_parse`
(Debug-identical `Completion` vs `parse_sse_reply` of the same bytes, same `request_bytes` /
`reply_bytes`), `stream_deadline_still_enforced_mid_stream` (`Unavailable::Deadline` with chunks still
arriving inside the read timeout), `stream_oversize_refused` (declared `Content-Length` over the cap),
`stream_forever_hits_cap` (flood with observer attached, deltas seen, cap still fires),
`observer_never_affects_request_digest` (captured request bytes and their sha256 identical with and
without an observer, equal to `request_digest`).
In `wire.rs`: `incremental_feed_equals_whole_parse` (feeds of 1..11 bytes and a mid-UTF-8 cut give the
one-shot parse's exact `Completion`), `reasoning_deltas_go_to_the_observer_only`,
`incremental_reader_is_as_strict_as_the_whole_parse` (broken JSON / data after `[DONE]` / non-SSE /
invalid UTF-8 refused at the feed that carries them).
