# P-37b — Policy planning for MCP capabilities

## What landed

All in `crates/harness-policy` (P-37 design note §5.4, §6.3, §9 step 1):

- `lib.rs` — the planner's lookup (`Lookup::One`) now carries the
  capability's **manifest and tier** beside the capability (private mirror
  of `admission::Resolved`), so planning can key on the transport.
  `Session::plan` maps `Resolved::One` straight through.
- **INV-6 for mcp-stdio:** an mcp-stdio capability sets
  `EffectiveClass::requires_conformed` in `plan_with`, whatever its class,
  so the existing plan-time check refuses the session
  (`NoConfinement`) without a `Conformed` witness, and `decide`'s
  defence-in-depth check covers it too.
- **Pinned-tier floor:** not folded into `EffectiveClass.confirmation`
  (that would ask *before* the user allow rules and make
  `pinned_tier_allow_rule_allows_unattended` impossible). Instead a new
  `Active::mcp` flag makes an mcp-stdio capability ask at `user_confirm`
  under the new rule [`MCP_DEFAULT_RULE`] = `ask.mcp.pinned`, placed in
  `decide` after the user allow rules and before the built-in default read
  allow — the same shape as the edit/exec default asks (§9 step 1: "deny →
  ask → allow → default deny with the pinned floor"). With no approver the
  ask is a deny (§5.2). A declared or dimension-derived floor above
  `user_confirm` still asks at step 2, before every allow rule, so the
  default can never lower one (`protected_action` floors never lowered).
- **Write/execute plan instead of `OutOfScope`:** exactly `Effect::Write`
  and `Effect::Execute` are lifted from the planning refusal for
  mcp-stdio; they decide through the pinned default ask. `irreversible`
  stays refused at planning (`OutOfScope "a non-read effect class"`) — the
  card names write/execute only, and refusing is the fail-closed reading.
- **Egress still refused:** the existing `OutOfScope "egress (the
  allowlist proxy is H4)"` row is unchanged; with the lift below it also
  fires for a granted sibling of an egress tool.
- **Process-level label lift (§5.4):** for an mcp-stdio capability,
  `egress`, `content` and `sensitivity` are raised to the max over ALL
  capabilities of its manifest (granted or not), computed once per
  manifest. Effect, blast radius and confirmation are NOT lifted. The
  lifted labels feed `trifecta` unchanged, so a server with one egress
  tool makes every granted tool of it an E/P/U source named by the
  refusal.
- **Quarantine re-runs the trifecta (§7.3):** `Session::quarantine` now
  takes the `WorkspaceDecl` (new private `Session.workspace` field) and
  returns `Result<(), SessionRefused>`: it recomputes `trifecta` over the
  non-quarantined active set plus the workspace. After a clean plan this
  cannot refuse (removal only shrinks labels); `Err` means "the remaining
  set is lethal, stop the run" and the capability is quarantined either
  way. No production callers yet (P-37i wires it), so the signature change
  is free.
- `builtin.rs` — `MCP_DEFAULT_RULE` (`ask.mcp.pinned`), re-exported.

## Required consequences in existing tests (not weakenings)

- The `plan_over` seam resolves through `Tier::Pinned` (the only tier that
  admits mcp-stdio), so every mcp-stdio fixture session now plans **with a
  witness**: the `spec()` helper defaults `conformed: true`, and the
  NoConfinement refusals are asserted in the tests that are about them.
- `classes_this_slice_does_not_decide_are_refused_at_planning`,
  `a_write_capability_that_merely_looks_like_submit_stays_out_of_scope`,
  `h2d_an_external_execute_capability_stays_out_of_scope` and
  `h2e_a_capability_that_merely_looks_like_the_checklist_stays_out_of_scope`
  moved to the new `fixture_inproc`/`cap_json_inproc` helpers (in-process
  transport), because an mcp-stdio write/execute now plans. Their
  assertions are unchanged; the undecided mcp class (irreversible) is
  asserted in the first of them.
- `inv_9_trifecta_is_refused_naming_one_source_per_label` and
  `inv_27_restricted_capability_refuses_the_session`: the lift changes
  WHICH source a label names (the granted sibling carries the whole
  manifest's maxima), and the "public workspace removes P" row now
  refuses via the process's own personal label; "any two labels without
  the third" now uses two single-capability manifests, since one lifted
  manifest cannot leave a label out. Each refusal still names one source
  per label.

## Ambiguity readings (fail-closed choices)

- Planner behaviour keys on the **transport**, not the tier: INV-6, the
  lift and the default ask apply to any mcp-stdio capability. Only pinned
  mcp-stdio admits today, and for a hypothetical signed one the ask is the
  stricter reading.
- `irreversible` mcp-stdio capabilities do not plan (card names
  write/execute only); `mcp_protected_action_never_allowed_by_rule`
  exercises the protected-action floor through a `shared` blast radius
  over the seam (pinned admission refuses `shared`, as it must).
- No journal record, no context change, no replay rule touched: decisions
  were already journaled with their rule ids and recomputed by audit, and
  this slice changes no rendered context — so no `context_format` bump and
  no `canon.rs`/`replay.rs` change (H-E/H-B respected).
- The CLI's per-capability class preview (`cmd_manifest.rs`) shows
  `requires_conformed` only for the execute class; the mcp-stdio
  requirement is already stated at transport level there ("the server is
  started only inside a conformed sandbox"), so no CLI change.
