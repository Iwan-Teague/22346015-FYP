# P-38c — Approval origin label and `LabelledApprover`

Implemented on branch `w/P-38c` (base: merge of w/P-35, `rh-complete`).

## What landed

- `harness-policy/src/approval.rs`:
  - `Origin { child: RunId, parent: RunId, parent_step: u64 }` — public fields
    (same style as `BoundCall`/`MintRequest`); every field harness-made.
  - `ApprovalRequest` gains a private `origin: Option<Origin>`, `None` from
    `new` (signature unchanged, so all existing call sites —
    `driver/approvals.rs` and the policy tests — compile untouched).
  - `with_origin(&self, Origin) -> Self` (clones; the loop hands a `&req`,
    so a consuming builder would not fit the §8 call shape
    `inner.ask(&req.with_origin(origin), deadline)`).
  - `origin()` accessor.
  - `Display`: with an origin the FIRST line is
    `asked by a helper (run {child}) started by run {parent} at step {parent_step}`,
    then today's lines byte-for-byte; without one the output is unchanged
    (golden test pins it).
- `harness-run/src/approve.rs`: `LabelledApprover<'a> { inner: &'a dyn Approver, origin }`
  implementing `Approver`: `kind()` is the inner kind (the journal keeps
  recording who really answered), `ask` forwards
  `inner.ask(&req.with_origin(self.origin.clone()), deadline)` — deadline and
  answer untouched; a `NoAnswer` stays a `NoAnswer` (deny, §5.3).

Not wired anywhere yet: the child run (P-38e) constructs the `LabelledApprover`
and the `Origin`. This slice is display + forwarding plumbing only, so no
journal record, no replay rule, no `rh-context` bump (nothing loop-visible
changed; the card's audit-clean requirement does not apply — no new event kind,
and `ApprovalRequested/Granted/...` bodies are untouched).

## Tests (all in the named modules)

- `approval::tests::approval_request_origin_line_first` — origin line first,
  remainder equals the unlabelled rendering.
- `approval::tests::approval_request_without_origin_display_unchanged` — golden.
- `approval::tests::origin_line_contains_only_ids_and_numbers` — hostile
  summary/args (control chars, bidi, JSON braces, a fake "run 9999 at step 9")
  cannot reach the origin line; exact-match + trusted-character-set check.
- `approve::tests::labelled_approver_forwards_kind_answer_and_deadline`.
- `approve::tests::labelled_approver_no_answer_is_deny`.

## Notes for the next slices

- P-38e should build `Origin` from the parent's `ToolStarted` intent data
  (`child` = new run id, `parent`/`parent_step` from the delegate step) and
  pass `Some(&LabelledApprover::new(parent_approver, origin))` as the child's
  approver; the child's `approver_present` stays the parent's.
- The origin line wording is pinned by two tests; if the wave consolidation
  rewords it, both tests and the design note §8 line must move together.
- `Origin` is `PartialEq, Eq, Clone, Debug` — enough for the child-run
  plumbing; no serde by design (display text only, nothing journaled from it).
