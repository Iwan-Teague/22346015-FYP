# P-03 — dev-only test workspace crate `harness-testkit`

## What

A new workspace crate, `crates/harness-testkit`, that holds the in-process
test fixtures three crates had been duplicating: the local-APFS locality
probe, the built-in manifest registry, the scripted-model reply builders,
a temp-disk fixture (state root + workspace) that cleans up after itself,
and a one-call scripted run + audit + journal reader. It is dev-only:
`publish = false`, no new third-party dependencies (only the workspace's
existing ones plus path deps on the harness crates themselves).

## API

- `Fixture::new(label)` / `Fixture::with_spec(label, spec)` — a unique
  temp base dir (`$TMPDIR/rustyharness-testkit-{pid}-{n}-{label}`) with
  `state/` and `ws/` subdirectories; `Drop` removes it. `write(rel, body)`
  creates parents. `spec` is a public field so tests can override it.
- `Local` — the locality probe every duplicated copy had (`MacOs`,
  `mnt_local: true`, `apfs`).
- `registry()` — the built-in manifest admitted at tier `Builtin`.
- `say` / `act(tool, args)` / `submit()` — scripted-reply builders.
- `read_spec(task)` — the read-only task spec (read/search/list grants).
- `run_scripted(&Fixture, replies) -> RunReport` — a real
  `harness_run::run` with the fixture's paths, a `ScriptedBackend`, the
  conservative profile and a 1,000,000-token budget.
- `assert_audit_clean(&Fixture, &RunReport)` — replays the run and fails
  on divergence, an unrecomputed stop, or an unanchored chain.
- `journal_kinds(&RunReport) -> Vec<EventKind>` — the attempt journal's
  record kinds.
- `cli(&Fixture, args, stdin_lines) -> (code, stdout, stderr)` — the CLI
  library in process (`harness_cli::main_with`) with the probe, gate-ok
  marker and an injected approver wired in.

## Conversions (proof)

- `harness-run/tests/run.rs` — the e2e/invariant tests now run through
  `run_scripted`; the refusal and custom-spec tests keep a local `drive`
  helper over the public `run` with `harness_testkit::registry()` (they
  need `NoProbe`, overlapping roots, symlinked workspaces, custom grants).
- `harness-run/tests/replay.rs` — fixture + scripted run + audit helpers
  all take the `Fixture`; the W4 probe delegates to the testkit's `Local`.
- `harness-cli/tests/cli.rs` — adopts the testkit's `Local` probe. Its
  in-process driver keeps its own approver wiring (`ApproverSource::None`)
  because those tests assert the unattended-deny behaviour, which the
  testkit's injected approver does not model.

## Checks

- `cargo fmt --all`
- `cargo clippy --locked --workspace --all-targets -- -D warnings`
- `cargo test --locked -p harness-testkit -p harness-run -p harness-cli`
