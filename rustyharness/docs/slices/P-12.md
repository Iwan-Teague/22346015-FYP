# P-12 — Sensitive-path default denies (`harness_policy::denies` + skip-and-count in the read tools + the CLI overlay)

## What landed

- `crates/harness-policy/src/denies.rs` (new module) — the default deny
  list as data and the two operations on it:
  - `DEFAULT_DENY_GLOBS`: `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`,
    `.aws/**`, `.ssh/**`, `.git/config`, `.npmrc`, `.netrc`
    (workspace-relative, `/`-separated; a pattern without `/` matches a
    name at any depth).
  - `default_denies() -> Result<UserPolicy, PolicyConfigError>`: 7
    capabilities × 10 globs of deny rules, each with a P-08 `path_glob`
    matcher, in a fixed capability-major × glob order (read, search, glob,
    list, then the three edits), so rule indices and the digest are
    stable across builds. Ask and allow stay empty.
  - `overlay_default_denies(policy)`: appends the defaults after the
    user's own rules; a policy that already names one of the default
    rules (same selector AND matcher) is refused as
    `PolicyConfigError::Ambiguous` — the duplicate-rule precedent, so a
    `--policy` that repeats the defaults is fixed, not silently merged.
  - `UserPolicy::denied_globs(&self) -> Vec<harness_core::glob::Glob>`:
    the compiled globs of the deny rules that cover the content-surfacing
    read tools (read, search, glob, list) and are exactly one `path_glob`
    (no argv conditions). Edit-only rules stay call-level. Infallible:
    the globs were compiled at load.
  - A library default stays EMPTY (`UserPolicy::default()`, OD-2): the
    run driver never applies defaults; an embedder calls
    `default_denies()` itself if it wants this behaviour.
- `crates/harness-policy/src/builtin.rs`: `SEARCH_ID`, `GLOB_ID`,
  `LIST_ID` consts (the ids existed only in the registration table).
- `crates/harness-policy/src/matcher.rs`: `Matcher::path_only_glob()` —
  the compiled glob when the matcher is exactly one `path_glob`.
- `crates/harness-tools`: `ReadTools::with_denied(Vec<Glob>)` (default
  empty). Search, glob and list skip what the globs match and SAY how
  many paths they skipped — `{n} path(s) skipped (denied by policy)` in
  the result's foot (search/glob) or after the listing (list). A denied
  directory is neither entered nor listed (its children are denied with
  it); a denied file is neither searched, matched nor shown. Nothing is
  dropped silently: denied is distinguishable from absent.
- `crates/harness-run/src/driver.rs` (`prepare`): the run's read tools
  are built with `policy.denied_globs()` — the one wiring point, shared
  by run and resume.
- `harness-cli`: `--no-default-denies` (a valueless flag, accepted by
  run, resume and replay). `inputs()` — shared by run/resume/replay —
  overlays the default deny list on whatever `--policy` was given (or on
  the empty one) unless the flag is passed. The effective policy
  (defaults included) is what the run header digests, so a replay or
  audit under a different overlay setting is refused by digest before
  any decision is compared; resume and replay must be given the same
  flag the run was given. The usage text names the list and the flag
  (golden test updated).

## Ambiguity resolution (fail-closed)

- The card asks for the flag to be "recorded in the header". The
  simplest fail-closed reading: the header already records the EFFECTIVE
  policy digest (§2.9, §7.1), and the overlay is part of the effective
  policy — a replay with the other overlay setting is refused on the
  digest with no new header field. Whether the manager wants a dedicated
  boolean alongside the digest is a consolidation question, noted here.
- The overlay refuses a duplicate default rule (exit 4, unreadable
  input) instead of merging, telling the user to remove the duplicate or
  pass `--no-default-denies` and write the list they mean.
- `harness-run` is touched (the card does not list it): unavoidable for
  skip-and-count through the real run — the read tools are built in
  `prepare()`. The change is one chained builder call.
- A call whose `path` argument itself names a denied path (read
  `.env`, or search with `path: ".env"`) is refused at the policy by the
  same matcher before the tools run; the tools' skip logic covers the
  WALK (what search/glob/list find and show), not a substitute for the
  call-level deny.
- Skips are counted per call, denied directories counted when the walk
  declines to enter them, denied files where they would have been shown
  or searched; the count counts only entries the walk actually reached
  (a list cut by its cap stops counting where it stops, like every other
  count in the tools).

## Not loop-visible beyond the results

No `context_format` bump: the skip-count line is TOOL OUTPUT — journaled
data the audit re-feeds verbatim (the P-16 precedent) — and the digest
rules are unchanged. The policy digest changes only when a policy
actually names these rules (then the run's own header says so, and the
same policy must be given to replay and audit).
