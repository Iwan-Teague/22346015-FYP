# P-39h — `harness.web.search` over the user's loopback SearXNG

Airlock design: `docs/slices/P-39-web-airlock.md` §8 (flow), §2.3 (policy),
§4.4 (budgets); INV-47 (untrusted, bounded, sanitised) and INV-43 (egress
journaled before any byte) hold end to end.

## What landed

- `harness-sandbox` `egress::open_hop` gained the search-endpoint branch:
  in `EgressMode::SearchEndpoint` the hop host must already be a loopback
  `IpAddr` (no resolution, `resolved: []`), the allow record is journaled
  as usual before the pump binds, and the pump dials the loopback address
  through the caller-provided connector (the provider passes
  `LoopbackConnector`). A non-loopback or non-IP host is refused with
  `refuse:no-address` journalled. The resolve+classify path moved verbatim
  into a private `open_hop_resolved` helper for the other modes.
- `harness-tools` `web.rs`: `WebTools` now serves `harness.web.search`
  alongside `harness.web.fetch`. Config type is
  `harness_model_core::endpoint::Endpoint` (`Endpoint::parse`: http only,
  127.0.0.1/localhost/[::1] only — the same loopback rule as the model
  endpoint; `https` refused). Constructors take `search: Option<Endpoint>`.
- The search hop: `GET <base>/search?q=<percent-encoded>&format=json
  &pageno=1&safesearch=1`, body cap 512 KiB (`SEARCH_BODY_MAX_BYTES`),
  request file `rh-fetch/1` with `accept: application/json`, run through
  the same `HopRunner` seam as fetch (so the confined fetcher path is
  unchanged; P-39j re-uses it for audit).
- Parsing is in process on `serde_json::Value`: only
  `results[].{url,title,content}` are read; every URL goes through
  `parse_url` (bad URLs dropped and counted in the header); titles cut to
  120 chars, snippets to 300, both terminal-sanitised; each entry marked
  `[fetchable]` or `[not on allowlist]`. The allowlist is never widened.
  The raw JSON is a blob for audit (its digest rides the `WebHop`); it
  never reaches the context. Output is `Untrusted<Vec<u8>>` with
  `Source::Web` (INV-47), like fetch.
- Query re-checked at the provider with `harness_policy::web::query_clean`
  (now `pub`; policy checked it at authorize — defence in depth, the same
  way the URL rule is re-checked).
- Budgets: `WebBudgets.searches` (default 10, max 100 per §4.4, validated
  in `assemble`), stateful on the provider like fetches; exhaustion is a
  typed refusal `WEB_BUDGET`. Results shown default 5, max 10
  (`max_results` arg).
- Error codes in `builtin::code`: `WEB_QUERY` 35, `WEB_NO_SEARCH` 36,
  `WEB_SEARCH_PARSE` 37 (non-200 or unusable JSON; garbage and missing
  `results` array are the same typed refusal).

## Decisions and deviations

1. **`harness-tools -> harness-model-core` dependency edge.** The design
   crate graph (§1.2) does not draw this edge, but the slice card names
   harness-model-core and reuses its loopback endpoint rule. It is a
   downward, acyclic edge into a pure crate; `purity.sh` checks only pure
   crates, so gates are unaffected. Recorded here and in the worker
   report as the one graph deviation.
2. **`query_clean` made `pub`.** Smallest change that lets the provider
   re-check the §2.3 rule; `MAX_QUERY_CHARS` stays private.
3. **`open_hop` search branch lives in harness-sandbox**, not in the
   provider: the journal-before-bytes invariant and the pump own the
   transport, so the mode's no-resolution rule belongs beside them.
4. **Result URLs render as `host:port/target`** in the observation (the
   design example omits the port); showing the port is the more precise,
   fail-closed rendering for a same-host-different-port allowlist.
5. **`localhost` maps to loopback without DNS** (model-endpoint rule);
   anything that would need resolution is refused by `Endpoint::parse`
   and, defensively, by the search-endpoint branch in `open_hop`.

## Loop visibility

The search egress record (`Egress`, purpose `search`, mode
`search-endpoint`, `resolved: []`, `ip` = the loopback address, url =
full request URL including the encoded query) plus the `ToolFinished`
hop record are the journal trail; audit recomputation wiring is P-39j.
No context-format bump: search adds a tool observation, no new rendering.
