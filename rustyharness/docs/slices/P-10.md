# P-10 — session events and context format `rh-context/6`

Implements the P-10 parts of `docs/slices/P-05-session.md` (§1, §2, §14).
No new dependencies. Crates: `harness-core`, `harness-journal`,
`harness-model-core`, plus exactly the two `Feedback::Answer` match arms in
`harness-run/src/driver.rs` (`first_render`/`draw`) the note assigns to this
slice.

## Journal (harness-journal)

- `EventKind`/`KINDS` gain the nine names once (hotspot H-E): the three
  defined kinds `UserTurn`, `TurnEnded`, `InputEnded` and the six reserved
  `ModeChanged`, `RuleGranted`, `Restored`, `InstructionsLoaded`,
  `ForkedFrom`, `ChildRun`. The canonical field lists of the three defined
  kinds are documented on the enum (the bodies themselves are written by
  P-13's loop; replay's `recorded()` rules are P-17). All nine are
  `needs_fsync()`.
- `writer::stop_cause_name` gains `StopCause::SessionEnded` →
  `"session_ended"` (the variant itself is harness-core's).
- `source_value`/`check_source`: the untrusted wire source
  `{"kind":"user"}` (`harness_core::Source::User`).
- Writer tap (§1.3): `Tapped { seq, step, kind, body }`,
  `JournalWriter::enable_tap` / `drain_tap`. Off by default; a record is
  tapped only after its write and its required fsync succeeded;
  `RunStarted` is tapped like any record, `RunStopped` is never drained
  (commit consumes the writer).

## Context (harness-model-core)

- `Message::User(Untrusted<String>)`: digest tag `u`, fields `["", text]`,
  wire role `user`. `render_request` runs the usual `shown` checks on it
  (invisibles stripped, `DelimiterCollision` refused) and treats any
  request holding a `Message::User` as a session request: `tool_choice` is
  omitted (batch requests, byte for byte, are unchanged — golden digests
  pinned in `batch_context_digest_unchanged` /
  `batch_request_render_unchanged`).
- `Feedback::Answer` renders as an assistant message in both protocols (no
  tool call, no feedback message), its index line is
  `- step N: answered the user (L bytes)`, and `model_texts` covers a
  native answer's reply.
- `build_session(profile, tools, task, facts, turns, users, shown)` with
  `UserEntry { before, turn, text, external }`; `Built.users_dropped`.
  Kept users = the longest suffix fitting
  `user_share_bytes - DROPPED_RESERVE_BYTES`; the oldest prefix renders as
  the single counted notice at the first user's position; an external
  change renders its notice immediately before its message; the step-turn
  window reserves the share (`window(.., reserved)`). `build()` (batch)
  shares the one internal builder with `reserved = 0`, `users = &[]`.
- Session texts of §2.5, verbatim: `SESSION_RULES`,
  `SESSION_PROTOCOL_TEXT`, `SESSION_PROTOCOL_NATIVE`,
  `external_change_text`, `users_dropped_text`, `SUBMIT_ACCEPTED_TEXT`,
  `SUBMIT_ACCEPTED_FAILING_TEXT`, `turn_end_text`,
  `budget_notice_session` (its `protocol` parameter is not used by the
  session texts — kept for the note's signature; the batch
  `budget_notice` is the one that names the submit tool).
- `SESSION_CONTEXT_FORMAT = "rh-context/6"`; batch keeps
  `CONTEXT_FORMAT = "rh-context/5"`.

## Harness-core

- `Source::User` (trusted intent, `Untrusted` mechanics) and
  `StopCause::SessionEnded`. Nothing in this wave writes either except the
  tests; the session loop is P-13.

## Deviations / notes for the manager

- The slice card's kind list omits `InputEnded`; the P-05 note (§1.1,
  §14: "3 defined, 6 reserved") is the spec and includes it, so it is
  reserved here. Likewise the header fields (`mode`, `turn_limits`,
  session `context_format`) are NOT written by P-10: the note's §14 gives
  them to P-13 (`HeaderInputs`/`HEADER_INPUT_KEYS`), and without the
  session loop no session header can be produced. `canon.rs` does not get
  a machine-readable field table — the canonical lists live in the
  `EventKind` docs, since body shapes are checked by replay (P-17), not by
  the reader.
- `budget_notice_session` keeps the note's `protocol` parameter although
  the session texts name no tool (noted above); drop it at consolidation
  if the owner prefers.
