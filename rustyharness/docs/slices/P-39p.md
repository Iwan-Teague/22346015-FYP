## The new test: the loop half of the forged-nonce row

P-39k's honest limitation said its `hostile_web_forged_nonce_in_page`
proved only the detection predicate (`wire::contains_nonce`), not the
loop's withholding. The loop-level behaviour already had a witness for the
*user-driven* case — `tests/hostile_session.rs`
`hostile_forged_nonce_in_tool_output_is_withheld` (P-19 hostile task 2),
where the test's user-turn closure plants the nonce. The new test is the
*model-driven* variant, which is the web case's actual shape: no user
cooperation at all. The in-test backend itself reads the nonce out of the
rendered request, writes it into a new workspace file, and has the model
read that file back. The loop must withhold the echoing observation
(H1i `first_render`), end the session cleanly through all three scripted
calls, keep the withheld body in the journal, and audit clean offline.

## Non-vacuousness battery (mutation evidence, this worktree, f105585 base)

Each row: the defence, the temporary break (reverted after the run), the
test that went red, and the green re-run on restored code. All runs on
macOS, toolchain 1.97.0 (this repo pins no rust-toolchain.toml; the
project gate is `sh scripts/ci/gates.sh`, whose clippy/test steps pass
with the default toolchain — with rustup 1.88.0 clippy two pre-existing
style lints fire in `harness-core` and `harness-sandbox-linux`, unseen by
the project's own gate).

  merged; nothing to type.

  research verbs (`harness-cli/src/inputs.rs` hard-sets
  `SessionKind::Coding`), and the session loop carries no web provider

  `driver/research.rs` `WebSources` has no constructor outside its
  module). The card's REPL/loop-level web rows land with the slice that
  wires the provider.
