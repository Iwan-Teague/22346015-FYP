# P-39a — pure egress rules (web airlock, pure half)

Slice card: `docs/slices/P-39-web-airlock.md` §14 row P-39a; rules are §4.1
(URL/allowlist) and §4.2 (classification). One new module:
`crates/harness-policy/src/web.rs`, wired with one `pub mod web;` line.

## What landed

- `parse_url` / `WebUrl`: absolute `http`/`https` URLs only. Byte cap
  ([`MAX_URL_BYTES`] = 4096), ASCII-only, no controls or spaces, exact
  lowercase scheme, no userinfo, DNS-name or strict-IP hosts, strict ports
  (digits, ≤5, no leading zeros, not 0), fragment dropped first, path+query
  kept verbatim as the request target with well-formed percent-encoding
  (never decoded), target must start with `/`.
- `Allowlist::load` / `allows`: ≤ [`MAX_ALLOWLIST_ENTRIES`] = 64 exact
  `(scheme, host, port)` tuples in a `BTreeSet`. Entry forms: `host`,
  `host:port` (https assumed), `http://host[:port]`. Refused at load:
  wildcards, leading/trailing dots, single labels, last label in
  {localhost, local, internal, arpa}, non-global IP literals, duplicates,
  `https://`-prefixed entries (BadEntry).
- `classify` / `AddrClass`: the §4.2 table verbatim. IPv4-mapped and
  NAT64 (`64:ff9b::/96`) addresses are classified by their embedded IPv4;
  `2002::/16` (6to4) is refused outright even with a global embedded
  address.
- `classify_answer`: empty refused, any non-global address refused (first
  offender named), else the first address in resolver order.
- `resolve_location`: RFC 3986 §5 subset (absolute, scheme-relative,
  absolute-path, relative-path), §5.2.4 dot-segment removal, query from the
  reference only, result re-parsed through `parse_url`, and an
  `https → http` downgrade refused (`UrlRefused::Downgrade`).

## Decisions taken (fail-closed readings of §4.1/§4.2)

1. Numeric shorthand hosts are refused outright, more uniformly than the
   grammar alone would force. `127.0.0.01`, `2130706433`, `0x7f.1` must be
   refused as IPv4 literals; a DNS-name fallback would still accept them as
   "names" that real resolvers re-read as addresses. So: a host of only
   digits and dots, or any `0x…` hex label, that is not a strict dotted
   quad is refused (`Host`). This also refuses `999.1.1.1`-style all-numeric
   names, which the design grammar `[a-z0-9-]` alone would accept — kept
   refused because it sits exactly on the reinterpretation hazard the slice
   exists to close. Flagged for the manager.
2. Pathless-query URLs (`https://host?q=1`) are refused as `Target`: §4.1
   says the target must start with `/` and only "path or path+query" forms
   are kept.
3. `https://`-prefixed allowlist entries are refused (`BadEntry`): the spec
   lists exactly three entry forms and https is the implicit default.
4. An `http://host` entry allows ONLY the `(http, host, 80)` tuple — exact
   matching, no scheme family. `docs.rs` likewise allows only
   `(https, host, 443)`.
5. Bracketed IPv6 with a port (`[2606:4700::1111]:8443`) is accepted in
   URLs and allowlist entries; v6 hosts are stored/rebuilt in canonical
   lowercased form and re-bracketed when an absolute URL is rebuilt.
6. The 2-label minimum is enforced in `parse_url`, NOT in the shared host
   grammar, so the allowlist can report single-label entries as
   `SingleLabel` (with its own reason) rather than a generic host error.

## Not in this slice

The §5 fetcher (connections), P-39b policy wiring, P-39c journal body.
Nothing here performs I/O, so nothing loop-visible changed; Cargo.lock
