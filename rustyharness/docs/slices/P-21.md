# P-21 — live chat tests and the developer mini-benchmark

Branch `w/P-21` (worktree). No new dependencies. Two deliverables: the
live chat tests the roadmap's P-21a names (`harness-cli/tests/chat_live.rs`,
`#[ignore]`d like the H1 exit tests), and the developer mini-benchmark
(P-21b) — a Rust dev binary crate (`crates/harness-minibench`, the bench
became a binary in 8be60c4; there is no bench script to update) plus ten
fixture tasks under `fixtures/bench/`.

## P-21a — `chat_live.rs`: two turns on a real model, both protocols

`chat_live_text_two_turns` and `chat_live_native_two_turns` run the real
`rustyharness chat` binary — the real locality probe, the real sandbox,
the real journal — against a loopback model server
(`RUSTYHARNESS_EXIT_ENDPOINT`, `RUSTYHARNESS_EXIT_MODEL`; same env vars
and `--ignored` invocation as `exit_h1.rs`). The input is a **piped
stdin** carrying two user turns, then EOF:

1. *find the codename hidden in the workspace and tell me*;
2. *write it to `p21.txt`*.

The test asserts, per protocol:

- **The answer**: some `ModelReplied` record's content contains the
  codename, and the session summary says `2 turn(s)`.
- **A verified edit**: an `harness.edit.*` tool ran, an `EditApplied`
  record is in the journal, and `p21.txt` is on disk containing exactly
  the codename.
- **The gate child's ending**: exit 5, `chain_head <hex>` then the
  `GateReport` whose last line is `Indeterminate { NothingChecked }`
  (`stopped: session_ended; no checks planned`) — a chat session runs no
  checks until H3, and its piped input ending is the stop.
- **A clean, anchored session audit.** The `replay` verb is batch-only —
  a batch audit refuses a session journal at its header's mode — so the
  test calls the session audit (`harness_run::audit_session`) directly,
  exactly as a future `replay --session` would: every record recomputed
  or re-fed and matched (`divergence: None`), the `session_ended` stop
  recomputed, and the chain head checked against the anchor taken from
  the run's own stdout (`anchored: true`).

Unattended means nobody to ask: the edit tools are allowed up front by an
explicit `--policy` file (the same rule `run` follows, tested there in
P-10), and the audit rebuilds the CLI's policy (file + default denies) so
its digest matches the header's.

## P-21b — `harness-minibench` and `fixtures/bench/`

A `publish = false` binary crate that runs every fixture task through the
**real driver** — real policy and default denies, real journal, real
pre-submit checks in the real sandbox — and records one TSV row per
fixture:

```text
harness  profile_sha  task  pass  steps  tokens  format_errors  cause
```

keyed by the harness version and the profile's `content_sha256`
(`--out FILE` writes the file; rows also go to stdout). The profile comes
from `--model` via `Profile::conservative_default`; the backend is the
same `OpenAiCompatible` client the binary uses, with the same startup
check. Tokens are the journal's `ModelReplied` `usage` (input + output);
format errors are the journal's `FormatError` records.

**A fixture** is a directory under `fixtures/bench/<name>/`:

- `task.json` — the CLI task-file shape (`task`, `grants`, `exec`,
  `presubmit`, `budget`), plus one bench-only key: `script`, the
  fixture's scripted solution (tool calls, then `{"submit": true}`) used
  by the self-test. The `presubmit.commands` are the expected check: a
  fixture passes when its submission is accepted with every check passing
  first time (`cause: Submitted`, `turned_back: 0`, `last: Passed` — the
  loop itself never releases `Passed`; the gate decides, so a submitted
  run stops `Indeterminate { NothingChecked }`).
- `repo/` — the files the task starts from, copied into a fresh
  workspace per run.

**The ten fixtures** (`01-hello-answer` … `10-two-file-report`) cover
create-a-file answers, fact-finding writes, `edit.replace` on read files,
a command-runner build, a workspace script run with `sh`, counting,
sorting, a multi-file repair and a two-input report. The checks are
`perl` one-liners; the `sh` fixture's script is itself in the repo.

**The gate self-test** (`minibench_scripted_all_pass`, in the binary's
`#[cfg(test)]`) drives all ten fixtures with their own scripts through
`run` with the production `SystemConfinement` and asserts every row
passes with zero format errors and a well-formed TSV line:

```text
cargo test -p harness-minibench
```

## Notes and residuals

- The bench is unattended: its policy allows the edit tools and the
  runner up front (a fixture run has nobody to ask), the default denies
  still underneath — the same policy shape the CLI builds from a
  `--policy` file.
- `conservative_default` admits five active tools; fixtures keep their
  grant lists at five including the submit sentinel.
- Running the bench against a model needs a local server (like the H1
  and P-21a live tests); the self-test needs a conformed sandbox
  (`#[cfg_attr(not(target_os = "macos"), ignore)]`).
- `chat` applies no task `budget` section (the P-18 deviation stands);
  the bench, which runs batch tasks, does apply its fixtures' budgets.
