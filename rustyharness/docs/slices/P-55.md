# P-55 — Fuzz-style tests for the Mach-O/ELF dependency parser (and the patch parser)

## What landed

- `crates/harness-core/src/objfile.rs`: a fuzz-style robustness section in
  the `tests` module, built on the P-54 mutator (`harness-testkit` was
  already a dev-dependency of harness-core). Named tests:
  - `fuzz_macho_parser_never_panics` — the shared driver runs 2 000
    seeded mutations (24 ops max) of each Mach-O corpus (a valid thin
    64-bit LE image, a 32-bit big-endian image, and a fat/universal
    archive whose host slice is this build's `HOST_CPU`) plus 2 000
    garbage draws per corpus. Every verdict is checked against the
    parser's contract: `Ok` ⇒ `is_object` agrees and every lib/rpath
    respects `MAX_ENTRIES`/`MAX_STRING`; `UnknownFormat` ⇒ the bytes are
    ≥ 4 and either `is_object` disagrees or the outer magic is a fat
    magic (see semantics below); any other error renders a non-empty
    message. The same seed re-derives the same bytes, so a failure is
    replayable from the case index in the assert message.
  - `fuzz_elf_parser_never_panics` — the same driver over an ELF corpus
    (64-bit LE, one `$ORIGIN` rpath, two DT_NEEDED entries).
  - `fuzz_macho_truncation_at_every_byte_is_typed_error` — the empty
    input is `TooShort`; every prefix of a valid thin image and of a fat
    archive yields a typed verdict, and an `Ok` prefix carries exactly a
    prefix of the whole image's libs/rpaths.
  - `fuzz_macho_bounds_hold_on_cyclic_dependency_fixture` — two Mach-O
    images that name each other (`@rpath/libb.dylib` /
    `@rpath/liba.dylib`) parse with the documented bounds intact;
    `candidates` on the untouched pair resolves through the rpath chain
    exactly as P-51 documents; then the driver mutates the pair
    alternately and asserts `Ok` verdicts stay within bounds and every
    candidate list is bounded by the rpath count (so cycles cannot blow
    up the parser's own output; the on-disk walk bound lives in
    `exec_libs`, out of this slice's crates).
  - Regression for the recursion bug below:
    `fat_archive_pointing_at_itself_is_typed_refusal`.
  - `#[ignore]`d long forms per target (`fuzz_macho_long_cases`,
    `fuzz_elf_long_cases`, `fuzz_macho_cyclic_long_cases`,
    `case_count(50_000)`) driven by `RH_FUZZ_CASES` +
    `cargo test -- --ignored`.
- Parser fix (the one production change, see semantics): fat archives can
  no longer recurse — `parse_macho` takes a `depth` parameter; a fat
  slice that is itself a fat archive is a typed
  `Malformed("a fat slice is itself a fat archive")` refusal instead of
  unbounded recursion. `fat_archive_pointing_at_itself_is_typed_refusal`
  pins it.

## The bug the fuzz loop found

`fuzz_macho_long_cases` at `RH_FUZZ_CASES=20000` stack-overflowed: a
mutation that sets a fat archive's slice offset to point back at a fat
magic (offset 0 = the archive itself) made `parse_macho → fat_slice →
parse_macho` recurse without bound. The fix is a fail-closed depth cap:
nested fat is refused as `Malformed`, everything else is unchanged. This
is beyond the card's "tests only", but `fuzz_macho_parser_never_panics`
could not hold without it; flagged for the manager (it arguably belongs
in P-51's record too).

## Semantics chosen (fail-closed readings of the card)

- **Fat-archive verdicts:** the parser dispatches on the *outer* magic;
  a fat archive's host slice is parsed and its verdict propagates
  verbatim. So a mutated archive whose slice is garbage reports the
  slice's `UnknownFormat` while the outer bytes still carry a fat magic —
  the `UnknownFormat` assertion accepts exactly that shape (bytes look
  non-object OR outer magic is fat) and nothing else.
- **Cyclic dependencies:** the card's cycles are exercised purely at the
  byte level (a self-referential pair of images); the resolve-time walk
  bound lives in harness-cli's `exec_libs`, outside this slice's crates.
- **Purity:** all fixtures are built in code (no fixtures on disk, no
  banned facilities; case counts come from the mutator's `case_count`).
