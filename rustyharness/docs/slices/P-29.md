# P-29 — Protected paths: `.git` and friends read-only by default

## What landed

- `crates/harness-tools/src/protected.rs` (new): the merged protected-path
  lists and the deny overlay.
  - `DEFAULT_DENY: &[&str] = [".git/**", ".rustyharness/**"]` — edits
    refused outright, exec sees the directories read-only.
  - `DEFAULT_ASK: &[&str] = [".github/**", "Cargo.lock"]` — the ask floor
    (CI config and lockfiles): an edit under one asks even under a user
    policy that allows edits.
  - `Protected::new(task_declared)`: the defaults first, then the task's
    declared globs, each compiled (`Glob::new`); a glob the compiler
    refuses refuses the whole list (fail-closed, `ProtectedError::Glob`).
    `Protected::empty()` for tools built without a spec. `matched(path)`
    returns the first matching pattern (the edit refusal names it).
  - `overlay_dirs(root, sources)`: the deny sources reduced to existing
    directories for the sandbox overlay — strips a `/**` suffix (a bare
    `**` protects nothing), joins onto the workspace root, skips missing
    bases and symlinks (`symlink_metadata`), canonicalises, dedups, sorts.
- `crates/harness-tools/src/edit.rs`: `EditEngine` holds a `Protected`
  (empty by default, `with_protected` to arm). A `guard` runs right after
  the `workspace_path` parse in `replace`/`multi`/`write` and in all three
  previews; a match is `EditError::Protected { pattern }`, mapped to tool
  code `PROTECTED` (23, `builtin::code`) with a message that names the
  pattern and tells the model to leave the path alone. Read tools are NOT
  restricted: `.git/config` stays readable (required test
  `read_of_dot_git_allowed`).
- `crates/harness-tools/src/exec.rs`: `ExecTools::with_protected_dirs`
  arms the overlay; `invoke` fills `ConfinedSpec.protected` (was always
  empty) with the prepared dirs, so the Seatbelt profile renders
  `(deny file-write* (subpath …))` after the read-write allow (the
  ordering profile.rs already had).
- `crates/harness-policy`:
  - `Matcher::path_glob(pattern)` — a public constructor for the one
    condition the harness itself writes (the same compile rules as the
    policy file's `path_glob` key).
  - `UserPolicy::push_ask(rule)` — appends to the ask list; a rule whose
    key (selector AND matcher) is already present in ANY list is
    `Ambiguous` (fail-closed, not silently doubled). `UserPolicy` already
    derived `Clone`.
- `crates/harness-run/src/driver.rs`:
  - `TaskSpec.protected: Vec<String>` — the task-declared list.
  - `protected_policy(user)`: the ask floor — for every `DEFAULT_ASK`
    glob × every edit cap (`harness.edit.replace`/`write`/`multi`), a
    user ask rule `{selector, matcher: path_glob}`. Applied INSIDE
    `plan()`, so a live run, a resume and an audit replay all decide with
    the same floor (the audit recomputes every decision). User ask rules
    fire before user allow rules (§5.1 step 2), so the floor survives a
    user `allow`; with no approver an ask is `deny no_approver`. A floor
    rule the user already stated verbatim refuses the run (`RunRefused::Protected`).
  - `prepare()` arms the edit tools (`Protected::new(task list)` —
    defaults included) and carries the compiled `Protected` in `Prepared`;
    `exec_tools()` reduces it with `overlay_dirs` for the sandbox.
  - Header field `protected`: `{task: <sha256 of the task's glob list>,
    deny_default: […], ask_default: […]}` — the task list is run input
    (digested), the defaults are build constants (listed). Added to
    `HEADER_INPUT_KEYS` (13 → 14): an audit or resume under a different
    task list, or a journal written by a build with different defaults,
    is refused by name ("the protected-path lists (task-declared or this
    build's defaults) differ from the recorded header"). This breaks
    replay of pre-P-29 journals — chosen deliberately (fail-closed); the
    `presubmit` precedent kept old journals readable because its default
    (absent) is unobservable, which is not true of a protection floor.
- `crates/harness-cli/src/inputs.rs`: `TaskFile.protected`
  (`#[serde(default)]`) → `TaskSpec.protected`; `deny_unknown_fields`
  still guards the section's shape.
- `crates/harness-testkit`: `read_spec` fills `protected: Vec::new()`.

## Ambiguity resolution (fail-closed)

- The card floats CI globs as `ask`-to-edit "not deny?" and lockfiles are
  not named at all; the card also says "Fail-closed default: edit denied
  for `.git/**`, ask for CI/lockfiles". Taken as the operative sentence:
  `.git/**` + `.rustyharness/**` deny, `.github/**` + `Cargo.lock` ask.
- The deny tier lives in the edit tools, NOT in policy: the tool refusal
  (code 23) is observable to the model and the journal either way, and
  edit tools are the only model write path today. The ask tier lives in
  policy because it must override a user allow rule — only the §5.1 order
  does that.
- Task-declared globs are deny-tier only (the edit tools refuse them);
  they add no ask rules — a refused edit asks nothing.
- `Trusted::Text` is compile-time-only, so the header records the task
  list as a digest, not as strings.

## Loop visibility (§4.1)

- Journaled: the header `protected` field at attempt start; a refused
  edit is a normal `ToolStarted`/`ToolFinished` with the refusal text.
- Replay: the audit recomputes the header field (`expected_inputs`) and
  re-derives the ask floor inside `plan()`, so every policy decision is
  recomputed identically.
- Context: no rendered-context change (the protection is invisible to the
  model until it touches a path), so `context_format` is NOT bumped.

## Tests (named as the card requires)

- `edit_into_dot_git_refused` (harness-tools edit.rs): replace,
  write-overwrite, write-create into `.git`, multi and all three previews
  refuse with `Protected{".git/**"}`; `.git/config` byte-unchanged; no
  `.git/hooks` directory created; a non-protected file still edits.
- `read_of_dot_git_allowed` (harness-tools builtin.rs): reading
  `.git/config` is a normal read, digest recorded.
- `exec_cannot_write_dot_git` (harness-sandbox/tests/conformance_macos.rs):
  `sh -c` append into `.git/config` with `protected=[ws/.git]` fails,
  file byte-unchanged, with an unconfined control showing the append
  works (macOS Seatbelt; suite is `cfg(target_os = "macos")`).
- `protected_list_in_header` (harness-testkit tests): header records the
  defaults and the task digest; a run without a task list digests
  differently; an audit given a different task list diverges naming the
  protected-path lists; the matching audit is clean.
- `task_declared_protected_path_refused` (harness-testkit tests): under a
  user policy that allows edits, `secrets/**` (task-declared) is refused
  by the tool, file unchanged, no `EditApplied`, the refusal names the
  protection, audit clean.
- `lockfile_edit_asks` (harness-testkit tests): under a user allow-edits
  policy, `Cargo.lock` is denied (`ask` floor, no approver →
  `no_approver`) while a read-then-edit of `README.md` succeeds; audit
  clean.
- harness-policy: `path_glob_ctor_builds_and_refuses_bad_globs`,
  `push_ask_appends_then_refuses_any_duplicate_key`.
- harness-cli: `protected_parses_when_present_and_is_empty_when_absent`.
- harness-tools protected.rs: glob compile/match defaults, task list
  extension, bad glob refusal, empty list, overlay reduction (strip,
  skip bare/missing).
