# P-38g — CLI: replay of children, sessions listing, chat lines

Card: surfacing P-38e/f subagents in the CLI — `replay` prints one line per
child audit and fails when any child fails; `sessions` hides child runs by
default and shows `child of <run>@<step>` with `--all`; `chat` shows
`[helper] started (run <id>, <n> steps)` and the delegate's report line;
approval prompts show the origin label (P-38c, no new code needed); the
usage footer reads `ChildRun.spent`.

## What was done

- `harness-journal` (`scan.rs`): `ScannedRun` gained `child_of:
  Option<ChildLink>` (`ChildLink { run, step }`), read from the header
  record's `mode`/`parent` fields. A malformed or missing link means the
  run is listed as a plain run (fail-closed for a display filter: hiding a
  run because of a parse failure would make runs disappear).
- `harness-cli` `cmd_sessions.rs`: `--all` lists child runs (appended
  ` child of <run>@<step>`); default list hides them and says how many
  were hidden. `sessions show --run <child>` never hides the named run.
  USAGE synopsis + the golden `usage_text_unchanged` updated together.
- `harness-cli` `cmd_replay.rs`: one `child run <id>: anchored|unanchored,
  no divergence|DIVERGED …` line per `AuditReport.children` entry; when a
  child diverged, the findings note names the helper run and the outcome
  is forced to `Indeterminate/UnreadableEvidence` (exit 5).
- `harness-cli` `render.rs`: `ChildRun` renders
  `[helper] started (run <id>, <n> steps)`; the delegate's `ToolFinished`
  renders `[helper] report -> <status> …` with the framed report as the
  sanitized preview instead of a plain `[tool]` line.
- `harness-cli` `usage.rs`: a `helpers` block (runs/steps/tokens/wall,
  `estimated` flag) summed from each `ChildRun.spent`, in JSON and words,
  beside the parent totals (not folded into them — see design questions).
- `harness-run` (bug fix found by this slice's replay test):
  `driver/plan.rs::plan` gained a `floor: bool` parameter. `audit_child`
  pre-applies the protected-path ask floor (the child's recorded header
  digests that policy), so re-applying it inside `plan` made every clean
  child audit fail with "the user policy already states a protected-path
  ask rule verbatim". All other call sites pass `true` (unchanged
  behaviour); child audits pass `false`.

## Design questions raised (fail-closed choices made)

1. Usage totals: the helpers' spend is shown as its own `helpers` block
   rather than added into the parent's token totals. The design says
   totals "include children"; a single blended number would mix the
   parent's server-reported tokens with the children's (possibly
   estimated) meter sums. The separate labelled block is the simplest
   reading that still shows the child spend; revisit if the gates want a
   combined number.
2. `sessions`: a run whose journal is unreadable is always listed (it
   cannot prove it is a child, so hiding it could hide evidence); the
   `child of` suffix appears in list lines and in `sessions show`.
3. Chat: the delegate's `ToolStarted` is not rendered at all (matching
   every tool); the two helper lines are `ChildRun` and `ToolFinished`.
4. `replay`: the child-line failure fold lives in the CLI because P-38f's
   `audit()` leaves the parent's own divergence/outcome untouched when
   only a child fails; the report JSON carries the folded outcome.
