# P-54 — Fuzz-style robustness tests (parsers of untrusted bytes)

## What landed

- `crates/harness-testkit/src/mutator.rs` (new module, no new crates): a
  seeded xorshift64\* generator (`XorShift64`: `new`/`next_u64`/`below`/
  `byte`; a zero seed is remapped to a fixed non-zero state) and byte
  mutation helpers — `mutate(bytes, rng, max_ops)` (bit flip, interesting
  byte, insert, delete, truncate, duplicate span; at most `max_ops` on a
  copy), `garbage(rng, len)` (exactly `len` bytes, uniform + a 22-entry
  `INTERESTING` table), and `case_count(default)`: the `RH_FUZZ_CASES`
  value when it parses as a non-zero count (capped at `MAX_CASES` =
  1 000 000), else `default`. Everything is deterministic per seed, never
  panics (no indexing, no unwrap), and is bounded — a fuzz loop can only
  terminate. No `rand`.
- The eight named tests, one per parser of untrusted bytes, each with a
  `#[ignore]`d `<name without _never_panics/_and_is_bounded>` long form
  (`fuzz_<target>_long_cases`) driven by `RH_FUZZ_CASES` +
  `cargo test -- --ignored`:
  - `harness-journal` `src/tests.rs`:
    `fuzz_journal_reader_mutated_valid_log_never_panics` (a real journal
    from `good_journal()`, mutated; `verify` must answer a typed verdict
    and the same seed reproduces the same mutation),
    `fuzz_journal_truncation_at_every_byte_is_typed_error` (every proper
    prefix of a valid journal is `Err` or — when it verifies — never
    `is_complete()`; the empty journal is a typed refusal; a prefix cut
    only at the final newline keeps all records and reports a torn tail).
  - `harness-core` `src/html.rs`: `fuzz_html_extractor_never_panics_and_is_bounded`
    (output ≤ `max_output_bytes`, links ≤ `max_links`, and the digest is
    always `sha256(text)`, for mutated pages and pure garbage).
  - `harness-core` `src/display.rs`: `fuzz_sanitiser_output_has_no_control_chars`
    (no `is_hidden` character survives raw — `\t` kept in both modes,
    `\n` in `Block`; output is a fixed point; `sanitize_for_terminal_bounded`
    at 128 bytes honours the bound and is idempotent too).
  - `harness-policy` `src/tests.rs`: `fuzz_policy_parser_never_panics`
    (strict JSON then `UserPolicy::from_json`: typed error or a policy,
    for a mutated valid v2 file with a `path_glob` matcher and garbage).
  - `harness-manifest` `src/tests.rs`: `fuzz_manifest_parser_never_panics`
    (`Manifest::parse` over mutations of `builtin::builtin_manifest_json()`
    and garbage, under a real `ValidationContext`).
  - `harness-cli` `src/config.rs`: `fuzz_config_parser_never_panics`
    (`UserConfig::parse` over a mutated full-key config and garbage).
  - `harness-testkit` `src/mutator.rs`: `mutator_is_deterministic_for_a_seed`
    (same seed ⇒ same stream and same mutations; different seed ⇒ a
    different stream; zero seed is a stream), plus boundedness and the
    `case_count` env contract.
- `[dev-dependencies] harness-testkit` added to harness-core,
  harness-journal, harness-policy and harness-manifest (harness-cli and
  harness-run already had it). `Cargo.lock` gained only those four dev
  edges — no version changes. Purity gate confirmed OK: dev edges are
  outside every normal/build tree it checks, and the pure crates' test
  code avoids the banned facilities (the `RH_FUZZ_CASES` read lives in
  harness-testkit, which is not purity-scanned).

## Semantics chosen (fail-closed readings of the card)

- **Ambiguity — "config" in harness-core:** the config parser is
  `harness_cli::config::UserConfig::parse` (`pub(crate)`, in
  harness-cli); harness-core has no config module. The test lives next to
  the parser (in-crate test module). Flagged to the manager.
- **Ambiguity — "ignored `RH_FUZZ_CASES` test":** read as: the named
  tests run modest counts in gates (`case_count(2_000)`), and each
  target also has an `#[ignore]`d long form whose count `RH_FUZZ_CASES`
  drives (default would be 50 000). Spot-checked the journal long form
  with `RH_FUZZ_CASES=5000`.
- **What each test asserts:** the parser's own documented contract, not
  just absence of panic — typed verdicts only (journal), documented
  bounds (html output/link caps, sanitiser's 128-byte bound), the digest
  invariant (html), idempotence (sanitiser), and reproducibility (the
  same seed re-derives the same input, so a failure is replayable from
  the printed seed + case index, which the assert messages carry).
- Case-count parity: the tests are deterministic (fixed seed bases), so
  gates and local runs see the same 2 000 cases per target.
