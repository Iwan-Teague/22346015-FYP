# P-44 — Pure HTML-to-text extractor (readability-lite)

## What landed

- `crates/harness-core/src/html.rs` — `to_text(&[u8], &ExtractLimits) -> Extracted`
  (`{title, text, links, truncated, digest}`), a pure, tolerant, linear
  tokenizer: no regex, no DOM, no tree, no unbounded state (a single
  skip slot, single-slot marker flags, a pre-depth counter capped at 4),
  so deeply nested input costs nothing.
- `crates/harness-core/src/lib.rs`: `pub mod html` + a doc line. No other
  file touched; no journal, replay or context-format change (P-44 is not
  loop-visible — nothing feeds the model context or a tool result yet;
  P-39/P-46 do that and journal the fetch + digest themselves).

## Semantics chosen (fail-closed readings of the card)

- **Input bound first**: bytes past `ExtractLimits::max_input_bytes`
  (default `MAX_INPUT_BYTES` = 2 MiB) are never read; the bound backs
  off to a UTF-8 character boundary. Invalid UTF-8 is lossy-decoded to
  U+FFFD. `truncated` covers input cut, output cut, or both.
- **Dropped**: `script, style, nav, aside, footer, form, iframe, svg`
  from the card, plus `template`/`noscript` (not rendered either — the
  fail-closed reading of "what a reader sees"). Skip-to-`</name` is
  case-insensitive and never ends early on nested look-alikes; an
  unclosed `script` swallows the rest, as in a browser. Comments
  (`<!-- -->`), doctypes and `<?…>` are skipped.
- **Kept, with markers**: `h1`–`h6` → `# …`/`### …` lines with a blank
  line after; `p`/`div`/`section`/`article`/`blockquote`/`main`/
  `header`/`dl`/`table`/`hr` start a blank-separated block; `li` →
  `- ` prefix; `td`/`th` join with ` | `, one `tr` per line; `br` breaks;
  `pre` keeps whitespace, newlines and interior blank lines. Whitespace
  outside `pre` collapses; the joined text is edge-trimmed.
- **Bounded output**: extraction stops at
  `max_output_bytes − marker reserve` and the text ends with the P-04
  marker spelling `[N bytes cut]`, where `N` counts document bytes after
  lossy decoding. The whole text then goes through
  `display::sanitize_for_terminal_bounded(…, Block, max_output_bytes)`,
  so no control/bidi/zero-width character survives raw and the final
  bound is guaranteed even if escaping expanded the raw text (in which
  case P-04's own marker replaces ours — still exactly one marker).
- **Links are data**: an `<a href>` yields `Link { href, text }` in
  document order, capped at `max_links` (default 256); href is
  entity-decoded, trimmed, stripped of control/invisible characters and
  capped at 2 KiB (longer = dropped). Nothing is resolved against a
  base, followed, or rewritten into the text; `javascript:` hrefs come
  through as inert data for the caller's policy. Anchor text stays in
  the text. A difference from the text path, deliberate: invisibles are
  DELETED from hrefs (they have no display path of their own here),
  while text keeps them escaped visibly by the sanitiser.
- **Title**: first `<title>` only, whitespace-collapsed, 2 KiB cap,
  `Option<String>`.
- **Entities**: numeric `&#…;`/`&#x…;` (semicolon required; out-of-range
  or surrogate → U+FFFD, and a decoded control char is escaped visibly
  by the sanitiser, not deleted) and a 43-entry named table of the
  common ones (`&nbsp;` → a plain ASCII space). Unknown names and bare
  `&` stay literal.
- **`digest`** (the card's `deterministic_digest`): SHA-256 over the
  final `text` bytes — the handle P-39/P-46 citations can journal.
- Bare `<` that starts nothing (`<3`, `<<`) is text. A tag that never
  ends degrades to text at the `<`. `>` inside quoted attributes does
  not end a tag. A `/>` outside quotes marks self-closing (an unquoted
  value ending in `/` can be misread as self-closing — tolerated).
- `truncated` also reports true if the text merely ENDS with the marker
  spelling: the claim errs visible, never silent.

## Tests (in-crate, `cargo test -p harness-core html`)

`extracts_title_and_paragraphs`, `drops_script_style_and_comments`,
`prompt_injection_text_is_kept_as_plain_text_not_interpreted`,
`malformed_unclosed_tags_do_not_panic` (17-case malformed corpus),
`deeply_nested_input_is_bounded` (50k `<div><ul><li>` and 10k `<pre>`),
`huge_input_is_truncated_with_marker` (output bound + input bound),
`output_has_no_control_or_bidi_characters`, `links_are_data_only`
(incl. the link cap), `deterministic_digest`, plus
`entities_are_decoded_and_unknown_ones_stay_literal`,
`markers_for_lists_tables_headings_and_pre` (format pin),
`invalid_utf8_becomes_replacement_without_panicking`,
`the_input_bound_never_splits_a_character`.
