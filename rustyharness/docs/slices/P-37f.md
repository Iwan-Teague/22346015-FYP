# P-37f — the pure MCP result renderer

Design note: `docs/slices/P-37-mcp-client.md` §9 step 5, §4, §12; INV-29.
Code: `crates/harness-mcp/src/render.rs`; two tool codes in
`crates/harness-tools/src/builtin.rs` (`code::MCP_TOOL_ERROR = 25`,
`code::MCP_RPC_ERROR = 26`); the `harness-mcp -> harness-tools` edge is a
design §2 edge, so no new crates.io dependency and no gate change beyond
adding `render.rs` to the pure-content checklist (`scripts/ci/purity.sh`).

## What landed

`render(line: &str, cap: usize) -> Rendered` — total and deterministic:
one raw response line (the exact bytes `wire::Frame` carried) plus the
result cap in; a `ToolStatus`, the text, the cut mark, and the SHA-256 over
the *full* text out. Audit (§12) re-feeds the journaled `mcp_response`
line and re-renders; any status/text/digest/truncated difference is a
divergence, so the render is a pure function of its arguments — nothing
clock-, environment- or state-shaped is consulted (the file stays on the
purity gate's scanned list; the same discipline as the P-37c codec).

Rendering rules (§9 step 5):

- `content` blocks in order: `text` blocks' strings joined `\n`; `image` /
  `audio` blocks become `[image omitted: <mime>, <n> bytes]` (MIME from
  `mimeType` when a string, else `unknown`; `n` = the `data` string's byte
  length, else 0 — the payload itself is never echoed); `resource` (nested
  `resource.uri`) and `resource_link` (top-level `uri`) become
  `[resource omitted: <uri>]`; anything else — an unknown `type`, a
  non-object block — is `[block omitted]`, with nothing echoed.
- `structuredContent` is the text only when **zero usable text blocks**
  were present; it then *replaces* any placeholder lines (one source of
  truth per observation) and renders as canonical JSON (`serde_json`'s
  writer orders object keys, so the canonical form is stable).
- `isError` strictly `true` (the JSON bool) → `ToolStatus::Error` with
  `MCP_TOOL_ERROR`; a JSON-RPC `error` object → `MCP_RPC_ERROR` with the
  server's `message` (untrusted, cut at `RPC_MESSAGE_MAX = 1024` bytes
  before the result cap) placed after harness-authored text; a line that
  does not classify as a response (unreachable live — the client state
  machine, P-37g, answers or drops it first — but the render is total)
  renders as a static harness notice under `MCP_RPC_ERROR`, echoing
  nothing from the line.
- The text is cut at `min(cap, MCP_RESULT_DEFAULT = 32 KiB)` (§4: the
  manifest's `max_result_bytes`, never above the default), at a character
  boundary (a straddling character is dropped whole), with `truncated` set;
  the digest is computed before the cut (the built-in tools' convention).
- Output carries `Untrusted::new(bytes, Source::Tool("mcp"))`: the
  provenance names the transport, because the render sees only the line;
  P-37g's provider narrows it to the called tool.

## Decisions worth remembering

- **The one sanitiser direction.** Server text is data and passes through
  verbatim (INV-29: a reply is never parsed; the nonce test pins that
  action delimiters inside tool output survive byte-for-byte). The only
  field cleaned is a resource URI *inside a harness-authored placeholder*,
  where the control/invisible set mirrors `harness_core`'s text extractor
  (`html.rs` `is_invisible`, kept in step by hand), so a URI cannot carry
  invisible code points into framing the harness wrote.
- **Degenerate text blocks.** A `text` block whose `text` member is not a
  string renders `[text omitted]` and does *not* count as a usable text
  block, so the `structuredContent` fallback still applies (fail toward
  showing the server's structured truth rather than empty text).
- **Cap clamped inside the render.** `render` takes the caller's cap but
  clamps it to `MCP_RESULT_DEFAULT`, so even a manifest bug cannot push an
  observation past the default.
- **Codes 25/26 only.** The card's harness-tools change is exactly the two
  `u16` constants; the renderer maps everything else onto `Ok`/existing
  variants, and never invents `Timeout`/`Crashed`/`Refused` from wire data.
