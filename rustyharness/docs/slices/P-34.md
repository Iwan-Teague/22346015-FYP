# P-34 — Journal tamper suite and REPL golden transcripts (eval)

Branch `w/P-34` (worktree). No new dependencies, no production code
changes: two new test files and one new in-crate test module, plus this
note. The card's "prove the evidence story under attack" is delivered as
properties, not anecdotes: every mutation class is applied systematically
to a real, writer-produced journal (and, for the audit side, to a real
scripted session's journal), and each must be reported.

## What was built

### Part (a) — tamper properties

**`harness-journal/src/tamper_tests.rs`** (reader level, pure `verify`,
exhaustive over the bytes):

- `tamper_every_line_flip_detected` — every single-bit flip of every
  byte of every line, and of every line separator, of a committed
  6-record journal (header, intent, result, `ModelReplied` with an
  inline and a blob payload, `BudgetCharged`, `RunStopped`). Every
  in-line flip is refused; the only flip the reader reports without
  refusing is the final newline, which turns the stop record into a
  torn tail (`torn_tail = Some(<tail start>)`, incomplete, no longer
  the anchored head) — the crash semantics, deliberately.
- `tamper_truncated_tail_reported` — truncation at every offset:
  `Empty` at 0, `TornHeader` inside line 0, otherwise a verifying
  prefix whose records are byte-identical to the original chain's
  prefix; the torn tail is reported exactly when the cut lands inside a
  line; `is_complete()` only for the uncut journal; no prefix matches
  the full journal's anchor.
- `tamper_rechain_detected_only_with_anchor` — a no-op re-chain
  reproduces the original bytes and head exactly (the encoding is
  deterministic); a re-chained `wall_used_ms` forgery and a re-chained
  user-text forgery (payload home restamped to match) both verify
  cleanly and are caught only by `check_anchor`.
- `tamper_structural_mutations_detected` — line drop / duplicate /
  adjacent swap / whole reversal (the first displaced record's
  `BadSeq` names the break; the seq check fires before the header and
  stop checks), a forged non-`RunStarted` header (`HeaderMisplaced`),
  body field swap (`BadHash`), three non-canonical re-encodings of
  every line (`NotCanonical`), validly chained and garbage bytes after
  `RunStopped` (`AfterRunStopped`), missing / altered blob / inline
  rewritten under a re-chain (`MissingBlob`, `UntrustedMismatch`), and
  a re-chained record claiming another attempt (`WrongRun`). Dropping
  the final `RunStopped` is the one mutation the reader cannot name:
  the journal still verifies but is incomplete and anchor-mismatched.

**`harness-run/tests/tamper.rs`** (audit level, `audit_session` on a
real scripted session — read, approved edit, two turns):

- `tamper_session_journal_mutations_detected` — one single-bit flip per
  line (all 8 bits), line drop, duplicate, adjacent swap, mid-line
  truncation (reader reports the torn tail; the audit does not vouch
  for the stop), bytes planted after `RunStopped`, and a
  non-canonical re-encoding: each makes the audit refuse to vouch
  (a divergence, a stop it cannot recompute, or a failed anchor).
- `tamper_rechain_detected_only_with_anchor` — the card's headline
  property, frozen at the audit level: a consistent re-chain of a
  re-fed clock fact (`wall_used_ms`) replays clean WITHOUT an anchor
  and is caught only by `--anchor`; a re-chained content forgery (the
  model's reply, restamped) diverges even without one, and either way
  the anchor names the replacement journal.

### Part (b) — golden transcripts

**`harness-cli/tests/chat_golden.rs`** — eight flows end to end in
process (`chat_cli` / `chat_cli_unattended`), compared byte-exactly
after normalisation: the fixture base path becomes `<base>`, maximal
32-hex runs (run ids, nonces) become `<hex32>`, maximal 64-hex runs
(chain heads, digests) become `<hex64>`, and the tool lines' live
milliseconds become `N ms`. Everything else — the banner, tool lines
with args and output previews, asks and grants/denials, edit and
restore lines, turn summaries, the session summary and outcome line,
the `chain_head` line and the `GateReport` JSON — must not drift:

`golden_chat_read_only_qa`, `golden_chat_edit_with_approval`,
`golden_chat_deny` (approver says no), `golden_chat_undo`,
`golden_chat_plan_build` (`/plan` → `harness.plan.submit` → `/build` →
edit of a planned file with NO ask — the `plan.allow` rule in action),
`golden_chat_resume` (the P-17 refusal, exit 4, plus the first
session's transcript), `golden_chat_hostile_output` (ANSI + bidi from
the model, escaped on the terminal), `golden_chat_budget_stop` (two
700k-token replies against the 1M budget: `stopped (budget)`).

## Fail-closed readings and notes

- **"resume" golden.** Reopening a session still needs P-17 (not in
  this build), so the golden freezes the refusal (`--resume <id>` →
  exit 4, "session reopen needs P-17 (not in this build); would resume
  <id>" on both streams, the report `CouldNotRun`) instead of a working
  resume. When P-17 lands, this golden is expected to change.
- **`/build` is silent by design (P-28):** the `ModeChanged` records
  are journaled and the widened set applies, but the sink prints
  nothing for `/plan` or `/build` themselves; the transcript shows the
  effect (the planned edit without an `[approve]` line).
- **Budget stop.** Chat's session budgets are
  `SessionConfig::defaults` (1M tokens); there is no CLI flag to lower
  them, so the golden drives the stop through server-reported usage
  (`ServerUsage`, the same lever `harness-run`'s own tests use). The
  token stop prints no `[budget]` sink line (those notices are
  threshold announcements, not stop reports); the frozen evidence is
  the summary line `stopped (budget)` and the finding
  `stopped: budget; no checks planned`.
- **Reader check order, now pinned by tests:** the sequence check
  (`BadSeq`) fires before the header-kind check (`HeaderMisplaced`) and
  before the after-stop check (`AfterRunStopped`); a duplicate of the
  last line is therefore `BadSeq`, and `AfterRunStopped` needs a
  correctly chained, correctly numbered record (or bare garbage after a
  torn stop, which is `NotARecord` or `AfterRunStopped`).
- **`torn_tail` is a byte offset** (start of the torn tail), not a
  record index; the tests pin that reading.
- **The edit tool's stale-read rule** ("file not read in this run;
  read it first") shapes the plan→build and undo flows: the model must
  read `a.txt` before rewriting it. The goldens freeze that order.

## Residuals

- The goldens are in-process (`main_with`); a real terminal's
  line-editing and the terminal approver's prompt text are not covered
  here (the approver in these tests is the silent scripted one).
- `audit`-level exhaustive sweeps (every bit of a session journal
  against `audit_session`) would be quadratic in replays; the session
  level pins one flip per line (all bits) and one mutation per class,
  and the reader level carries the exhaustive properties.
