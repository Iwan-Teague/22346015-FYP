# P-18 — `rustyharness chat`: the line REPL (v1)

Branch `w-P-18` (worktree). No new dependencies. `harness-cli` gained the
`chat` verb (`cmd_chat.rs`), the REPL input (`repl.rs`) and the record
renderer (`render.rs`); `Cx` gained two embedder seams (`input`,
`backend`); `harness-testkit` gained the `chat_cli`/`chat_cli_unattended`
drivers. `chat` is a gate child: its last stdout line is the session's
`GateReport`, and every session so far ends
`Indeterminate { NothingChecked }` (exit 5) until H3.

## What was built

- **The verb** (`rustyharness chat [--workspace .] --task --profile
  [--endpoint] [--resume [<run-id>] | --continue] ...`). The usual gate
  child plumbing: options → `GateId` → config (P-07) → bundle fill (P-14)
  → the session loop → `chain_head` + `GateReport`. `--resume` and
  `--continue` are parsed in a pre-pass (`--resume` consumes a value
  unless it is absent or another option), because `options_with_flags`
  has no optional-value form. A duplicate `--resume`/`--continue` is a
  usage error through the report path.
- **Banner** (stderr, before the first prompt): workspace, state root,
  model profile id and endpoint, the confinement witness or "no
  confinement: read/edit only" (`harness_sandbox::available()` is asked
  only when the task grants `harness.exec.run`, mirroring `run`), the
  granted tools, and the effective policy's digest (`UserPolicy` exposes
  only its digest, never its rules).
- **The REPL** (`repl.rs`): line input, `"""` multi-line blocks (joined
  with newlines; an unterminated block at EOF is delivered as-is and
  noted), slash commands handled between turns while the wall clock is
  paused: `/help /status /tools /policy /sessions /resume /todo /usage
  /diff /clear /exit`. Empty lines are ignored. A message that
  `UserMessage::new` refuses (empty after trim, or over the 64 KiB bound)
  never reaches the session: it is noted and the prompt continues.
  `/clear` ends the session cleanly and starts a new one in the same
  process; `/exit` (or Ctrl-D/EOF) ends the session; either way the
  session's ending is `InputEnded` + `RunStopped { session_ended }`.
  `/sessions` delegates to the `sessions` verb's own code path (its data
  lines go to stdout); `/usage` reads the current attempt's journal and
  prints the P-15 usage in words; `/diff` is a stub until P-40;
  `/resume` refuses (see Residuals).
- **Input sources**: `Cx.input` is `InputSource::Stdin` (the binary) or
  `InputSource::Given(&[String])` (tests, embedders). Stdin lines are
  forwarded by one background thread (`chat-stdin`, the same pattern the
  terminal approver uses), because a blocked read cannot be given a
  deadline.
- **The approver in chat** (`ChatApprover`): a REPL must not start a
  second stdin reader, so at a real terminal (`InputSource::Stdin` +
  `is_terminal()` + a config `approver` that is not `none`) the approver
  and the input share the one line feed: the approver drains stale lines,
  prints only `approve this one call? [y/N] ...` (the request line itself
  comes from the sink), and answers `y`/`yes` as yes, any other line as
  no, nothing by the deadline as no answer. Anywhere else — a pipe, an
  embedder-given approver, config `approver: "none"` — the run verbs'
  rules apply unchanged; nobody at the terminal is `None`, and the
  policy then denies every ask outright (reason `no_approver`, shown as
  `[deny] ... (no_approver)`).
- **The renderer** (`render.rs`), an `EventSink` (P-05): display only,
  everything through `harness_core::display` sanitisation. Model text is
  shown streamed per `ModelReplied` (block mode, bounded), cut at the
  first `<action>` span (display-only courtesy, not a parse); tool calls
  render as one line `[tool] <capability> <args> -> <status> (<ms> ms)`
  with a short output preview, the duration measured between the sink's
  `ToolStarted` and `ToolFinished` (the journal has no duration). Tool
  arguments are recovered from the preceding `ModelReplied`'s
  `tool_calls`, matched to the journaled call digest exactly (the same
  canonical `{"args":…,"capability":…}` digest `harness-policy` mints);
  a call that cannot be matched shows the capability alone. Edits show
  `[edit] <path> applied`; approvals show short request/granted/denied/
  expired lines; `FormatError`, `LoopDetected`, `BudgetNotice` and deny
  decisions each get a line. Every untrusted payload is resolved from
  its payload home (inline text `unescape`d, or `blobs/<sha256>` read)
  and sanitised — nothing raw from the model or a tool ever reaches the
  terminal (INV-2 discipline).
- **Ending**: after the last session, a summary line on stderr (run id,
  attempt, turns, steps, stop cause), the outcome in words, a best-effort
  run bundle (P-14), then the gate contract: `chain_head <hex>` and the
  `GateReport` as the last stdout line, exit 5 (`NothingChecked`), no
  marker.

## Fail-closed readings (this build)

- **`--resume` / `--continue` refuse**: reopening a session journal (the
  P-17 records `Restored`/`ForkedFrom`, re-feeding the journal's turns)
  is P-17's work, which is parallel to this slice and NOT merged here.
  Fail-closed: an explicit `--resume <id>` (or the `--continue` picker,
  which resolves the newest session by `RunStarted` wall clock via
  `scan_runs`) is refused with exit 4 and a note naming the run it
  *would* resume: "session reopen needs P-17 (not in this build)". No
  session is started. `/resume` refuses the same way in-band.
- **`chat_session_journal_audits_clean` is the journal reader, not the
  audit**: the batch `audit()` refuses session journals by mode (P-13),
  and P-17's session audit is not in this build. The test therefore
  asserts what this build can honestly check: the verifying reader opens
  the attempt journal (the chain verifies), the tail is not torn, the
  record shape is the session shape (`RunStarted` … `UserTurn`,
  `ModelReplied`, `ToolStarted`/`ToolFinished`, `TurnEnded`, `InputEnded`
  … `RunStopped { session_ended, indeterminate:nothing_checked }`).
- **No P-16 diff preview**: `EditTools::preview` needs the `Call` and
  `ReadLog` the run loop holds; the CLI layer cannot reach them. The ask
  is shown as the sink's request line (`[approve] <capability> (<tier>)
  needs approval`) plus the approver's own prompt; the P-16 in-loop diff
  preview is not wireable here.
- **Session budgets**: a chat session runs on the P-05 defaults
  (`SessionConfig::defaults`: 500 steps, 4 h wall, 50 steps / 3 format
  errors per turn, 24 h input idle), not on the task file's `budget`
  section — the simplest reading of the P-05 spec for interactive use;
  noted as a deviation (the task's budget is a header input for `run`).
- **Ctrl-C**: no signal handling crate is available and raw-mode termios
  is forbidden (`unsafe_code = "forbid"`), so Ctrl-C kills the process
  without the gate report. This is documented behaviour for v1; the gate
  contract is kept on every clean path (EOF, `/exit`, `/clear`, model
  unavailable, budget stop).
- **Slash-command output** goes to stderr (human lines), except
  `/sessions`, whose listing is data and goes to stdout through the
  `sessions` verb's own path.

## Named tests (all in `crates/harness-cli/tests/chat.rs`)

- `chat_runs_two_prompts_and_prints_chain_head` — two messages, two
  answers, EOF; exit 5, `chain_head` + GateReport as the last stdout
  lines, "2 turn(s)" in the summary.
- `chat_streams_text_to_output` — the model's text reaches stderr as it
  is replied.
- `chat_denies_asks_without_tty` — unattended (no approver): the edit
  ask is denied by policy (reason `no_approver`, shown as `[deny]`), the
  file is NOT created, the session continues.
- `chat_approves_edit_with_diff_shown` — a `y` approves; the request
  line and the edit are shown; the file is written with the approved
  content.
- `chat_slash_status_lists_tools` — `/status` and `/tools` show the
  workspace and the granted tools; then a normal message still runs.
- `chat_resume_continues_previous_session` — a first chat session is
  created; `--resume <id>` and `--continue` both refuse with exit 4,
  naming P-17 and the run id.
- `chat_output_has_no_raw_escape_from_model` — a reply carrying raw ESC
  sequences reaches the terminal only escaped (`\u{1B}`), never raw.
- `chat_eof_ends_cleanly_exit5_report_line` — immediate EOF: 0 turns,
  clean ending, exit 5, `chain_head <64 hex>` then the GateReport.
- `chat_session_journal_audits_clean` — the journal reader verifies the
  chain; the session record shape is as P-05 specifies (see the
  fail-closed note above for why this is not the P-17 audit yet).

## Residuals

- `/resume` and `--resume`/`--continue` become real when P-17 merges;
  the refusal names it.
- `/diff` is a stub until P-40.
- The streamed reply is re-printed per `ModelReplied` record, not
  character-by-character; "streams through P-06/P-04" is honoured at the
  record boundary the journal provides.
- Tool-call duration is measured at the sink (the journal records no
  duration), so it includes only the observed emit-to-emit gap.
- A turn's tool arguments are shown from the reply that proposed them;
  if that reply is older than the most recent one (unusual retry
  shapes), the line falls back to the capability name alone.
