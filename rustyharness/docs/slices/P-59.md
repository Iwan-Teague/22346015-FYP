# P-59 — Minibench: profile files, both protocols, journal audit, regression gate

## What landed

All in `crates/harness-minibench/src/main.rs` (no new dependencies; no
changes outside the crate).

- **`--profile FILE`** — a recorded profile JSON, loaded with the same
  strict `Profile::parse` the CLI's `--profile` uses (unknown fields
  refused, nulls where a default is wanted refused, everything in range),
  so the text and native protocols and any recorded profile run. It is
  the alternative of `--model` (a profile carries its own model id; both
  together are refused). The TSV's `profile_sha` cell is always the
  profile's `content_sha256` — for `--model` runs that is the
  conservative default's digest, so a live row and a scripted row of the
  same profile compare equal.
- **`--only NAME[,NAME]`** — the named fixtures only, in the order given.
  A name that is no fixture is refused (a typo must not silently shrink
  the bench).
- **`--keep DIR`** — after each run, the attempt's journal directory
  (`journal.jsonl` + blobs) is copied to `<DIR>/<task>/<run-id>/` before
  the fixture's state root goes away.
- **`--audit`** — after each run, `harness_run::audit` replays the
  produced journal with the run's own task spec, policy, profile and
  budget limits, anchored by the run's own chain head. No divergence and
  an anchored chain head, or the row is marked `audit_fail` (its `pass`
  drops to `fail` and the TSV cause cell says `audit_fail`), one
  `audit_fail` anywhere fails the bench (non-zero exit).
- **`--baseline FILE`** — a recorded TSV of the bench's own shape, read
  by column name. A task that passed in the baseline and fails a majority
  of its attempts now is a REGRESSION; steps grown by more than 50% and
  at least 3 over the recorded steps fail too; rows recorded by another
  harness version are compared but flagged (a note, not a failure). Two
  recorded rows for one task is refused; tasks not in the baseline (or
  not run now) are noted, not compared.
- **`--repeat N`** — rows are per attempt; the gate passes a task on a
  majority of its rows (a tie is a fail). `--out FILE` writes one row per
  attempt, so a written file can itself be a baseline.
- **`docs/bench/`** — recorded results: `<date>-<model>-<protocol>.tsv`
  plus a `README.md` table. It opens with
  `2026-10-02-scripted-text.tsv`, the deterministic baseline recorded
  from the scripted self-test (all ten fixtures pass through their own
  `script` solutions, conservative default profile, text protocol); live
  recordings follow the same naming.

Exit codes: 0 every task passed its majority (and no `audit_fail`, no
baseline regression), 1 the gate failed, 2 the bench could not run (bad
arguments, a refused profile or baseline, an unreachable endpoint, no
fixtures).

## Tests

New in `main.rs`'s test module (`cargo test -p harness-minibench`):

- `profile_file_sets_profile_sha_in_row`
- `invalid_profile_file_refused`
- `only_filter_runs_named_fixtures`
- `audit_flag_marks_divergence_as_audit_fail` (a doctored journal copy —
  one byte flipped mid-chain — must not audit clean, and the marking
  turns the row into an `audit_fail` fail)
- `baseline_regression_on_newly_failing_task`
- `baseline_step_growth_flagged` (both thresholds: past both fails,
  below the 3-step floor does not)
- `baseline_other_harness_version_flagged_not_failed`
- `repeat_majority_rule`
- `keep_dir_receives_every_journal`
- the scripted self-test grows: `minibench_audit_flag_passes_on_scripted_run`
  (a real scripted run's journal audits clean and anchored) and
  `minibench_baseline_regression_detected` (a baseline of the scripted
  run's own rows passes; doctoring the row into a failure is detected).

## Notes and open questions

- The brief's `devkit/glm/profiles` and `devkit/local/profiles` do not
  exist in this tree; `--profile FILE` takes any profile file path, so
  recorded profiles run wherever they live. No `devkit/` files were
  invented for them.
- Audit anchoring uses the run report's `chain_head`, the same anchor the
  CLI prints (`chain_head <hex>`); a run that left no durable chain head
  is an audit failure rather than an unchecked pass.
- Baseline step growth compares each attempt against the recorded steps
  and fails on the first attempt past both thresholds; with `--repeat`,
  one wild attempt therefore flags. Simplest reading of "steps grew by
  more than 50% and by at least 3" per row; flagging on any attempt is
  the fail-closed choice.
