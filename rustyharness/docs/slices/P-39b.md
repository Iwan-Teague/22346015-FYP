# P-39b — the policy side of the web airlock

Follows P-39a (`web.rs`: URL grammar, exact-tuple allowlist, address
classification). This slice makes the airlock plannable and decidable; it
opens no network connection and adds no dependency. The fetcher and the
driver wiring come later.

## What the design asked for, and what landed

- `SessionKind { Coding, Research(WebGrant) }` on `SessionSpec`
  (`harness-policy/src/lib.rs`). `Coding` is `Default`, so every existing
  caller is unchanged apart from naming the new field in struct literals
  (`harness-run`'s planner and `harness-tools`' test rigs).
- `WebGrant { allowlist: Vec<String>, search: bool, confirmed:
  Option<WebConfirmation> }`. The allowlist entries are the raw config
  strings; policy parses them with `Allowlist::load` at planning and
  REFUSES the session on a malformed entry
  (`WebSessionRefused::Allowlist`), so a typo can never become "allow
  nothing". `confirmed: Option<WebConfirmation>` (tty | flag): `None`
  refuses the session (`WebSessionRefused::Unconfirmed`) — the egress
  floor is met once, at session start, never per fetch.
- A research session is refused: with any workspace
  (`WorkspaceGranted`), with personal data (`PersonalData`), without the
  confirmation (`Unconfirmed`), holding anything but the four research
  ids (`GrantOutsideResearch`), with an ask rule on a web id
  (`OutOfScope{what: "ask rules on web capabilities (per-fetch prompts
  are never offered)"}`); a malformed allowlist
  (`WebSessionRefused::Allowlist`). A coding session granting a web id is
  refused (`WebGrantInCoding`) — defence in depth; the registries
  already keep the ids apart.
- All of these run AFTER the trifecta, so a private workspace in a web
  session is named as the trifecta it is.
- `research_manifest_json()` / `research_manifest()` in `harness-manifest`
  (`head + web_fetch + web_search + task_todo + task_submit + tail`;
  todo/submit fragments reused byte for byte). The research bytes are
  pinned (`research_manifest_bytes_pinned`,
  `d677f855…4c6de37c`); the coding pin is untouched. The web ids are NOT
  in `TERSE_TABLE` (that would change the coding `tool_docs` digest).
- The decide web branch sits after the user deny rules and the schema
  check, before the ask rules. Fetch: `parse_url` → `deny.web.url`;
  exact-tuple allowlist match → `allow.web.session-allowlist`, else one
  of `deny.web.scheme` / `deny.web.port` /
  `deny.web.host-not-allowlisted` (`Allowlist::mismatch` in `web.rs`).
  Search: 1..=256 chars, no control/zero-width/bidi (`query_clean`) →
  else `deny.web.query`; no endpoint → `deny.web.no-search-endpoint`;
  else `allow.web.search-endpoint`. The branch NEVER returns `Ask`.
- The plan-time egress refusal and the decide-time
  `deny.egress-unavailable` now exempt exactly the two web ids (planned
  in `Research`, flagged in `Active`), so the 64 KiB of unchanged
  behaviour outside the airlock stays unchanged
  (`egress_still_out_of_scope_in_coding_sessions`).

## Judgement calls (honest, minimal, fail-closed)

- The card's trifecta wording "workspace/workspace/web": the unchanged
  `trifecta` function names the FIRST source per label, and a web fetch
  is `content: third_party`, so U comes from the fetch, not the
  workspace: `Trifecta { private: "workspace", untrusted:
  "harness.web.fetch", egress: "harness.web.fetch" }`
  (`web_session_refused_with_workspace_grant` asserts this). Security
  outcome identical; the record is exact.
- `WebSessionRefused` / `WebCallRefused` are new public enums; the design
  names rules, not Rust variants. Messages are static text.
- `DenyReason::Web(WebCallRefused::Url(UrlRefused))` reuses P-39a's
  `UrlRefused` rather than duplicating reasons.
- The 257-character search query is denied by the SCHEMA
  (`deny.args-schema`, maxLength 256) one layer before the branch; the
  branch's own `deny.web.query` covers the empty and invisibly
  corrupted queries the schema cannot speak. Both are tested.
- The registration table `BUILTIN_TOOLS` is the union (11 coding + 2
  web, web last). `harness-tools`' three-way agreement test now asserts
  the coding prefix + the web suffix; the tools dispatch table itself is
  unchanged (no fetcher yet). `tool_count_policy_default_read_allow`
  (policy) now checks each id resolves in exactly the manifest that
  declares it.
- `WebConfirmation` (tty | flag) is carried but only its presence is
  decided on this slice; the journal form of the session-start
  confirmation is the driver slice's business.
