# P-39c: journal kinds for the web airlock

Done on branch `w/P-39c` (worktree `.wt-w-P-39c`), 2026-10-02.
Card: `docs/slices/P-39-web-airlock.md` P-39c (§4.5, §6, §7; hotspot H-E).

## What changed

Crates touched: `harness-core`, `harness-journal` only.

- `harness-core`: `Source::Web(String)` — provenance for bytes fetched over
  the network; the string is the URL. Like every `Source` string it is
  outside text, so it is escaped wherever it is recorded.
- `harness-journal/src/event.rs`: the `Source` wire arm —
  `{"kind":"web","url":…}`, URL escaped with `canon::escape`.
- `harness-journal/src/reader.rs`: `check_source` accepts the `web` wire
  source (`kind` + escaped `url`, exactly two keys). Without this the
  reader would refuse any journal that records a web fetch.
- `harness-journal/src/canon.rs` (hotspot H-E, done once here):
  - New kinds `NoteSaved`, `NoteImported` (§6, §7), added to the closed
    set and to `needs_fsync` (a resume reads notes back from the journal;
    `Egress` was already fsynced — appended before any bytes are
    forwarded).
  - `canonical_body_keys(kind)`: the §4.5 `Egress` list
    (`decision,host,hop,ip,mode,port,purpose,resolved,url` — 9), `NoteSaved`
    (`bytes,note,sources,turn` — 4), `NoteImported`
    (`bytes,confirm,note,path,sha256` — 5), sorted like the wire; `None`
    for kinds whose bodies their owners still define.
  - `check_canonical_body(kind, body)`: exactly those keys and the §4.5/§6/§7
    value shapes — `decision` `allow` or `refuse:` + closed reason set
    (`non-global-address`, `no-address`, `dns-timeout`, `budget`,
    `host-not-allowlisted`, `downgrade`); `host` a lowercase DNS name or IP
    literal (shape backstop only; the authoritative check is P-39a's);
    `ip` null | IP | `delegated`; `mode`/`purpose` closed sets; `port`
    ≤ 65535; `resolved` a list of IPs; `url` an untrusted payload home with
    `source.kind == "model"`; the note ids and `sha256` 64-hex digests;
    `confirm` exactly `typed-id-prefix` (INV-50); `bytes`/`path` untrusted
    payload homes. Kinds without a list are untouched, so no existing
    journal changes shape.
  - Host/IP parsing uses `core::net::IpAddr` (`canon.rs` stays I/O-free;
    no new dependency).
- `harness-journal/src/writer.rs`: `write_record` calls
  `check_canonical_body` before anything is written and refuses a mismatch
  as `InvalidEvent` — the writer is NOT poisoned (a malformed event is a
  harness bug, like a duplicate key).
- `harness-journal/src/layout.rs`: `research_notes_dir(state_root)` =
  `<state_root>/research/notes` (§6, INV-49: notes live under the state
  root, not inside a run directory, named by the note's 64-hex id).

## Notes for the manager / later slices

- Nothing writes `Egress`/`NoteSaved`/`NoteImported` yet. `harness-run`'s
  replay (`feed.rs`) still treats them as "not a shape the loop writes"
  (the `Egress` name falls into its reserved catch-all); P-39f/P-39j own
  the re-feed. No audit hole today: no producer exists.
- `canonical_body_keys` returning `None` for undefined kinds is what keeps
  this slice from touching other kinds' owners: the writer polices only
  what is defined, so a later slice defines its list here without touching
  the writer (the H-E point).
- `Trusted` has no null variant, so a null `ip` cannot be written through
  `Event::field` today; the shape (and the reader) accept it, and P-39f can
  add a `Trusted` variant if the loop needs to write it. The allow-path
  journal writes the resolved address, `delegated` covers user-proxy.
- `old_journal_still_reads` was NOT regenerated: its fixture predates
  P-39c on purpose (the strongest form of "old journals still read").
- `docs/01-design-v0.1.md` and the README Status table are untouched, per
  the card.
