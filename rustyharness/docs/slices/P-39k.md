# P-39k — Hostile suite and eval row for web research

## Numbering resolution (recorded because the two docs disagree)

`docs/ROADMAP-parity.md` §"P-39 slices" card **P-39k** ("Hostile suite and
eval row for web research") points at `docs/slices/P-39-web-airlock.md`
section 11 row "P-39k". The design note's card table has since grown from 11
cards (a–k) to 16 (a–p); the card literally keyed **P-39k** there is the CLI
card, and the card matching the roadmap title is **P-39p** ("Adversarial
airlock suite (tests only)", §11 adversarial table) plus an eval-plan row.

The CLI card is not completable on the merged base either: its P-39j twin
(egress over the journal writer) is already merged, and
`harness-cli/src/inputs.rs` still says "the CLI's verbs run coding sessions;
the research session's verbs arrive with the web slice", so there is no CLI
surface to test. This slice therefore implements the hostile-suite reading:
**design-note P-39p as far as the merged base allows, plus the eval-plan row**
(§5, new row E12).

## What landed

- `crates/harness-testkit/src/hostile.rs` (new) — shared hostile-web
  fixtures, panic-free and purity-clean (no TLS, no new third-party deps):
  - `FixtureServer` — scripted HTTP/1.1 server bound on `127.0.0.1:0` with
    three modes: scripted response blobs (one per connection, then write-side
    shutdown and a short drain), an endless chunked flood (4095-byte chunks
    forever), and a slowloris dribble (partial response head, a few bytes at
    a time, stopping as soon as the client socket errors). Accepts counter
    for "how many sockets did this call actually open" assertions.
  - `FakeResolver` — `harness_sandbox::egress::Resolver` answering from a
    queue (so a second query for the same name can differ: DNS rebinding),
    counting calls.
  - `RecordingLog` — `EgressLog` capturing `EgressRecord`s; `decisions()`
    renders the journal-first record order as `"allow"` / `"refuse:<reason>"`.
  - `InProcessHopRunner` — `harness_tools::HopRunner` that reads the hop's
    `req.json`, parses it with `harness_fetch::read_request`, dials the
    fixture's proxy port, and runs the real `harness_fetch::fetch_over`.
- `crates/harness-run/tests/hostile_web.rs` (new) — 23 tests driving
  `WebTools` through a policy-planned research session (`Session::plan` with
  a `Research(WebGrant)`), `authorize`, a journal `ToolStarted` intent, and
  `invoke` with the egress log attached (the session loop cannot carry
  `WebTools` yet — see limitations).
- `docs/ROADMAP-parity.md` §5 — new eval row **E12** for the web hostile
  suite.
- `crates/harness-testkit/Cargo.toml` — normal deps on `harness-fetch` and
  `harness-tools` (both pure, no features); `crates/harness-run/Cargo.toml` —
  dev-dep on `harness-fetch` (frame forging in the lying-fetcher tests).

## The hostile classes covered (§7 of the airlock note, one test each unless noted)

Injection and marking: `hostile_web_prompt_injection_in_page` (injection
survives verbatim as inert `Untrusted(Source::Web)` data),
`hostile_web_forged_nonce_in_page` (a page containing a run nonce trips
`harness_model::wire::contains_nonce`, the predicate the loop's withholding
rule uses), `hostile_web_terminal_escapes` (CSI/OSC/bidi/zero-width all
rendered as literal `\u{...}` spellings, no raw control bytes),
`hostile_web_search_snippet_injection` (same for titles/snippets, plus the
`javascript:` URL dropped and counted, cut limits at 120/300 chars, no raw
JSON in output).

Redirect and DNS attacks: `hostile_web_redirect_to_metadata_ip`,
`hostile_web_redirect_to_private_via_dns`, `hostile_web_dns_rebinding`
(second answer non-global after a successful first hop),
`hostile_web_mixed_answer` (any non-global address in the answer refuses),
`hostile_web_ipv4_mapped_v6` (`::ffff:10.0.0.1` classified as its embedded
IPv4, refused "private").

Budget and resource bombs: `hostile_web_giant_response`,
`hostile_web_endless_chunked`, `hostile_web_slowloris`,
`hostile_web_header_flood`, `hostile_web_gzip_bomb` (identity-only
`Accept-Encoding` means `Content-Encoding: gzip` is refused before the body
is read), `hostile_web_zip_as_html` (NUL sniff wins over the claimed
content type).

Framing and typing: `hostile_web_content_type_games` (quoted charset ok,
unknown charset refused, upper-case header cannot smuggle),
`hostile_web_smuggling_shapes` (CL+TE, duplicate CL, TE with an encoding —
each an `http_parse` refusal, three rigs).

Fetcher betrayal: `hostile_web_fetcher_lies_short_body`,
`hostile_web_fetcher_lies_binary_in_text_frame` (the harness re-sniffs the
frame body itself: NUL in a `text/plain` frame is refused `WEB_BINARY` even
though the frame "parsed"), `hostile_web_fetcher_lies_not_a_frame`,
`hostile_web_fetcher_lies_over_cap` (declared `body_len` over the cap
refused before the body is trusted).

Evidence: `hostile_web_note_poisoning` (see limitations — partial),
`hostile_web_audit_offline` (the live hop's frame + `HopIo` replayed through
`WebTools::new_replaying` with `RecordedHops`/`RecordedResolver` produces a
`WebRecord` byte-identical to the live one, identical egress records, and
the fixture's accept counter never moves — zero sockets in the offline half,
INV-51).

## Fixture placement

`harness-testkit` gains only remap-free fixtures. The `RemapConnector` and
the per-test `Rig` stay inside `harness-run`'s test crate:
`RemapConnector` is behind `harness-sandbox`'s `remap` feature, and feature
unification only puts that type in reach of a build whose own dependency
edge enables it (`harness-run`'s dev-deps already do, added with P-39j).
The testkit library itself compiles against default features and never
names the gated type, keeping the purity script's "no normal dependency
edge enables a test-only feature" rule intact.

## Purity

No TLS anywhere: `harness-fetch` and `harness-tools` are pure
(`harness-fetch` speaks plain HTTP/1.1 only), the new dependency edges add
no features, and the default build's `Cargo.lock` grows only path deps.
Every egress is journaled before it happens (INV-43): each test asserts the
`RecordingLog` decision order (`allow` before the hop's bytes appear in the
response, `refuse:*` for every refused hop), `harness-run/src/egress.rs`
(P-39j) holds the journal-first unit tests, and `hostile_web_audit_offline`
proves the recorded evidence alone reproduces the run.

## Honest limitations

- `hostile_web_import_without_typing` is **not implemented**: the import
  path (P-39m) is not merged, so there is nothing to type or import. The
  typed-note behaviour it guards cannot exist yet.
- `hostile_web_note_poisoning` covers the **session half only**: a research
  session submits a note that reads like a policy-mutating instruction, the
  research audit stays clean, and a subsequent coding session's header and
  journal show no trace of the poison (no grant, no `web` key,
  `rh-context/7` unchanged). The "note file the next run reads" half waits
  for P-39l (persistent notes), which is not merged.
- The named suite in the card counts 21 tests; this slice ships 23 (the four
  lying-fetcher variants split one card row) and skips the two cases above.
- `harness-cli/tests/hostile_research.rs` from the design-note card is **not
  feasible**: the CLI has no research verbs yet (`harness-cli/src/inputs.rs`
  states they arrive with the web slice).
- The hostile tests drive `WebTools` directly through the policy-planned
  session + journal seam rather than the session loop, because the loop
  still refuses research specs that grant web ids
  (`plan.rs`: "this build wires no web capabilities into its driver").
  Loop-level coverage lands with the slice that wires the provider.
- The forged-nonce test proves the detection predicate
  (`wire::contains_nonce`) rather than the loop's withholding behaviour,
  which lives in `driver/step.rs` behind `pub(crate)`.
- `JournalEgress` is `pub(crate)`, so hostile tests observe journal-first
  ordering through `RecordingLog`; a future slice could re-point these tests
  at the real writer once it is exported for tests.
