# P-37g — journal kinds and `ToolFinished` MCP fields

Implements §11 of `docs/slices/P-37-mcp-client.md` (the slice card's parts
that live in the journal). No new dependencies. Crate: `harness-journal`
only.

## Journal (harness-journal)

- `EventKind`/`KINDS` gain three names once (hotspot H-E): `McpConnected`,
  `McpDrift`, `McpStopped`. The canonical field lists of the three kinds
  are documented on the enum (the bodies themselves are written by the
  driver wiring, P-37i; replay's `recorded()` rules are P-37j). All three
  are `needs_fsync()` — inputs or provider-state changes resume keys on.
- The enum doc also records the optional `mcp_request_id`, `mcp_request`,
  `mcp_list`, `mcp_noise`, `mcp_response` fields a `ToolFinished` of an
  MCP capability carries (§11), beside its usual fields.
- No reader change: the reader is body-schema-agnostic and already accepts
  any canonical body whose untrusted payload homes verify, so the new kinds
  and fields round trip as-is, and old journals read unchanged (the pinned
  `old_journal_still_reads` fixture is untouched).

## Deviations / notes for the manager

- The card names `unknown_kind_still_refused` and `old_journal_still_reads`;
  both already existed from P-10. They pass unchanged in behaviour; the
  first was extended with two more forged kind names.
- §11's "replay::recorded refuses `mcp_*` fields on a non-MCP capability
  and an MCP `ToolFinished` without them" is harness-run (P-37j), outside
  this slice's crate list. No writer-level refusal of `mcp_*` keys was
  added either: the writer's body rules are only the reserved-key ones it
  already had, matching the P-10 precedent (shapes are replay's job).
- No `context_format` bump: nothing rendered in context changed, and no
  code writes the new kinds yet.
