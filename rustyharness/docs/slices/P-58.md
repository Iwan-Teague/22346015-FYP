# P-58 — Docs: user guide, `--help` completeness, version and changelog

Slice card: `docs/USER-GUIDE.md` (install, quickstarts for a local and a
hosted model, every verb, policy/profile formats, workspace modes, the
security model, limits), every verb's `--help` complete and tested,
`CHANGELOG.md`, version 0.2.0 in the workspace manifest. Crates:
harness-cli, docs. Deps P-23/P-26/P-28/P-31 all merged in the base.

## What landed

- **`--help`, centrally (H-A intact).** `main_with` answers `--help`
  before any dispatch: bare (full usage), or after a verb path the new
  `is_verb_path` names (a verb, or one of its subverbs — `schedule add`
  etc.). `args::help_for(path)` extracts the verb's synopsis entries
  from USAGE itself (prefix match on the command path, so `schedule
  --help` shows all four schedule subverbs) and appends a pointer to the
  full usage for the shared notes; USAGE stays the one text (the golden
  `usage_text_unchanged` still pins it byte-for-byte, updated for the
  additions below). Unknown paths keep the ordinary usage error —
  `bogus --help` and `run --task x --help` exit 2 (fail closed).
- **USAGE completed** (the verbs and flags the text had fallen behind):
  an `apply` entry; run's `--workspace-mode`, `--scratch-with-git`,
  `--allow-session-grants`, `--accept-edits`; chat's `--workspace-mode`,
  `--scratch-with-git`, `--allow-session-grants`, `--accept-edits`,
  `--fork RUN@STEP`; replay's `--accept-edits`; resume says which run
  options it does not take. `apply` was dispatchable but invisible.
- **One grammar fix, fail-closed direction.** `run`/`resume`/`chat`/`acp`
  took `--allow-session-grants`/`--accept-edits` as VALUE options whose
  value was ignored (`contains_key`), while replay took them flagless
  and USAGE (acp's line) showed them flagless everywhere. They are now
  valueless on all four verbs: `--accept-edits garbage` is refused as an
  unknown option instead of silently meaning "on". No test or doc relied
  on the value form; the P-23 comment ("the session-grant flags" in the
  flag list) and the acp usage line already described the flag form.
- **The gate children's option lists** (`RUN_ALLOWED`, `RESUME_ALLOWED`,
  `REPLAY_ALLOWED`, `RUN_FLAGS`, `RESUME_FLAGS`) hoisted from
  `gate_child`'s inline literals to consts beside it — same values, now
  readable by the usage tests.
- **Tests** (named in the slice card):
  - `dispatch::tests::every_dispatch_verb_has_usage_text` — every verb
    in the new `VERBS` const names itself in USAGE.
  - `dispatch::tests::usage_mentions_every_flag_of_chat_and_run` — every
    option of run (`RUN_ALLOWED` + `RUN_FLAGS`) and chat
    (`cmd_chat::ALLOWED` + `FLAGS`, now `pub(crate)`) appears in USAGE,
    plus `--resume`/`--continue`/`--fork`.
  - `tests/help.rs::help_for_each_verb_exits_zero` — the real binary
    answers `--help` (and every verb path + `--help`) with exit 0 and
    usage text that names the verb.
  - `tests/help.rs::help_anywhere_else_stays_a_usage_error` — the
    fail-closed counterpart (unknown verb, options after a verb).
  - `dispatch::tests::readme_quickstart_commands_exist_as_verbs` — every
    `rustyharness ...` / `cargo run -p harness-cli -- ...` command in the
    README's fenced blocks names a verb path the dispatch answers
    (`is_verb_path` is the oracle).
  - `dispatch::tests::session_grant_flags_take_no_value` and
    `args help_renders_for_every_verb_path` pin the grammar and the
    per-verb extraction.
- **`docs/USER-GUIDE.md`** — install, 5-minute quickstart (local model;
  hosted through a loopback proxy), `profile init`/`check`, `doctor`,
  `run`/`resume`/`replay`/`events`/`review`/`compare`, `chat` (slash
  commands, fork/resume), `sessions`/`gc`/`apply`, `schedule`, the
  policy and profile file formats, workspace modes, defaults/config, the
  security model in plain words, limits. Facts cross-read from the verb
  sources, `docs/hosted-proxy.md` and the merged slice notes.
- **`CHANGELOG.md`** — 0.2.0 entry summarising the merged slices'
  user-visible behaviour, an 0.0.x entry for the H1/H2 internal
  releases. **Version bumped 0.0.1 → 0.2.0** in the workspace manifest;
  `Cargo.lock` regenerated by cargo (member versions only, H-F's
  `cargo update -w` path).

## Loop-visibility checklist

Not applicable: help text, docs, the changelog and the version number
are outside the loop — nothing here changes what a run journals, what
`replay::audit` re-derives, or the rendered context (`rh-context/6`
stands; no `context_format` bump). The usage-text change is visible to
the person at the terminal only; `usage_text_unchanged` is its golden.

## Judgement calls

- 0.0.1 → 0.2.0 skips 0.1.x entirely, per the card; the changelog says
  so ("the first internal releases (0.0.x)") rather than inventing
  0.1.0 entries.
- The session-grant flag grammar fix is the one behaviour change; it
  aligns four verbs with the text replay, the comment and the acp usage
  line already promised. Manager may prefer to revert it and document
  the value form instead — reverting means putting the flags back on the
  value lists and rewriting the run/chat usage lines.
- `help_for` prints synopsis entries plus a pointer, not the shared
  notes, so per-verb help stays short and cannot drift from USAGE; the
  card's "complete" is read as "every verb has help, every flag named".
- The README was not edited (the quickstart already existed and the new
  test reads it); the Status section untouched, per the brief.
