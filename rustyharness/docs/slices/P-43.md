# P-43 — `rustyharness doctor`

## What

A new verb that inspects the machine + install and prints one PASS/WARN/FAIL
line per check, each with a one-sentence fix:

```
rustyharness doctor [--endpoint <url>] [--state-root <dir>]
```

Checks (in print order):

1. **sandbox** — `cx.confinement.require()`. Conformed: PASS with the
   backend, matrix row and probe digest. Refused: WARN ("refuses: …"),
   because the read/edit half of the agent works without a confinement
   backend (commands stay off via `harness.exec.run`).
2. **state-root** — `config::state_root` (flag over config over the default,
   which doctor creates owner-only like every P-07 verb; explicit roots are
   never created). FAIL when absent/not a directory (`fix: mkdir -p …`) or
   not on a local filesystem (P-12 locality); WARN when the mode is wider
   than 0700.
3. **config** — strict `config::load()` (P-07). Unreadable/invalid: FAIL
   with the parser's message, but doctor keeps going; no file: PASS.
4. **endpoint** — flag over config (`config::value`). None: WARN. Built
   client refuses a non-loopback URL: FAIL (it can never work; no
   connection is made). `list_models` answers: PASS with the model list;
   unreachable: WARN (the server may simply not be up yet).
5. **profile** — config's profile, else `<config dir>/profiles/default.json`.
   Missing/unparsable: FAIL; parses but stamp not valid: WARN; `validated()`
   (P-16 stamp): PASS with the model name.
6. **presets** (P-11) — the preset anchors' programs (`cargo`, `node`,
   `python3`, `go`) looked up on PATH via `exec_presets::look_up` (now
   `pub(crate)`); missing ones are a WARN with the affected presets named.
7. **terminal** — stdin TTY: PASS; not a TTY: WARN (every ask would be a
   deny without an allow policy).

Exit 0 when nothing FAILed, 1 otherwise (2 for bad usage). Every detail
string goes through `sanitize_for_terminal(…, Line)` (P-04). No network is
opened except the given (loopback-only) endpoint. Doctor is not a gate
child and not loop-visible: no journal records.

## Files

- `crates/harness-cli/src/cmd_doctor.rs` — the verb (new).
- `crates/harness-cli/src/dispatch.rs` — one dispatch arm.
- `crates/harness-cli/src/lib.rs` — `mod cmd_doctor;`.
- `crates/harness-cli/src/args.rs` — USAGE line + golden test in unison.
- `crates/harness-cli/src/exec_presets.rs` — `look_up` made `pub(crate)`.
- `crates/harness-cli/tests/doctor.rs` — six tests, in process, against a
  mock OpenAI-compatible server on loopback.

## Tests

`doctor_all_pass_with_mock_server` (exit 0, no FAIL, mock server hit once,
default state root created), `doctor_fails_without_state_root_and_says_how`
(exit 1, `mkdir -p` fix, nothing created), `doctor_warns_on_non_tty`,
`doctor_reports_unreachable_endpoint` (closed port => WARN, exit 0),
`doctor_output_has_no_raw_escapes` (0x1b in the `--state-root` argument
never reaches output), `doctor_exit_code_follows_fail`.

## Decisions / notes

- Sandbox refusal and unreachable endpoint are WARN, not FAIL: doctor's
  exit code would otherwise be 1 on every box without a sandbox backend or
  with the model server not yet started. A non-loopback endpoint is FAIL
  (client refuses at build; deterministically unusable).
- A stamp is unkeyed (P-16), so the tests mint a valid stamp directly;
  no `profile check` subprocess is involved.
- Test note: the fixture writes the profile under
  `$RUSTYHARNESS_CONFIG_HOME/rustyharness/profiles/default.json` —
  `config_dir()` appends `rustyharness` to the override home too.
- `doctor_all_pass_with_mock_server` asserts exit 0 while the sandbox line
  may be WARN on hosts without a backend (macOS CI conforms via Seatbelt).
