# P-09 — Mechanical split of `driver.rs` and `replay.rs` into submodules

## What landed

`crates/harness-run/src/driver.rs` (2818 lines) and
`crates/harness-run/src/replay.rs` (1445 lines) are split into submodules
with **no behaviour change** (pure code motion). Every function name of
P-05 §12 kept. This is the merge-first slice P-13/P-17 build on.

- `driver.rs` (473 lines) keeps the module doc, the public types
  (`TaskSpec`, `RunConfig`, `Run`, `RunRefused`, `RunReport`), `run()`,
  the meter constructors `new_meter`/`new_meter_resumed` (both must stay
  in this file: `scripts/ci/purity.sh` pins `Meter::new(`/`Meter::new_resumed(`
  to `driver.rs` exactly), the identity helpers `random_bytes`/`new_run_id`/
  `new_nonce`, and `pub use harness_tools::{ReadLog, StaleRead};`.
  It declares `pub(crate) mod` for the six submodules and carries a
  `pub(crate) use` re-export block so `replay.rs`'s flat
  `use crate::driver::{...}` keeps working unchanged.
- `driver/plan.rs` — `Prepared` (+`providers`), `prepare`, `exec_setup`,
  `attempt_check`, `loop_facts`, `facts_block`, `plan`, `create_run`,
  `todo_for`.
- `driver/header.rs` — `HeaderInputs`, `SandboxRecord`, `ExecHeader`,
  `HEADER_INPUT_KEYS`, `limits_fields`, `builtin_manifest_sha256`,
  `header()`.
- `driver/step.rs` — `Loop` (+fields, all `pub(crate)`), `BudgetNotices`,
  `NonceSource`, `Flow` (was private, now `pub(crate)`: `stop.rs` names it
  in signatures), `journal()`, `drive`, `remaining_wall`, `step`,
  `budget_notices`, `step_inner`, `observe_budgets`, `feed_stall`,
  `first_render`, `draw`, `request`, `model_error`, `shown_reply`,
  `fe_name`, `BUDGET_DIMS`, `budget_key`.
- `driver/tools.rs` — `is_edit`/`is_exec`/`is_read` (`is_read` was private,
  now `pub(crate)`), `RecordedResult` (+`into_result`), `RecordedEdit`,
  `exec_tools`, `SCRATCH_DIR`, `exec_fields`, `end_name`, `parse_exec`,
  `status_name`, `Loop::capability`.
- `driver/approvals.rs` — `Approvals` (+`new`), `Loop::approve`.
- `driver/stop.rs` — `End`, `commit`, `Loop::refused`, `Loop::loop_stop`,
  `decided`, `deny_name`, `denied_text`, `loop_name`, and the private
  `denial_tests` module (moved with `denied_text`, its only user).
- `replay.rs` (98 lines) keeps the module doc and re-exports the public
  surface: `pub use audit::{audit, Audit, AuditRefused, AuditReport};`,
  `pub use compare::Divergence;`, `pub use resume::{resume, Resume};`.
- `replay/feed.rs` — `Recorded`, `recorded()`, `approval_of`, `status_of`,
  `digest_at`, `recorded_facts`.
- `replay/compare.rs` — `Divergence`, `diverge`, `Compared`, `compare`,
  `compare_recomputed`, `compared_body`, `wall_seqs`, `is_wall_condition`,
  `check_wall_conditions`, `expected_inputs`, `check_header`,
  `header_mismatch`.
- `replay/audit.rs` — `NOT_SAMPLED`, `UNREADABLE`, `attempts_desc`,
  `has_header`, `run_dir_of`, `recorded_outcome`, `Audit`, `AuditReport`,
  `AuditRefused`, `audit()`.
- `replay/resume.rs` — `Chain`, `Resume`, `resumable_attempt`, `resume()`.

Public paths are byte-identical to before: the split modules are
`pub(crate)`, so the only reachable paths stay
`harness_run::{run, audit, resume, ...}` plus the `driver`/`replay` module
paths that already existed. New guard:
`crates/harness-run/tests/public_api.rs`
(`public_api_paths_unchanged`) names every public path — function-pointer
ascriptions for `run`/`audit`/`resume` at the crate root and at
`driver::`/`replay::`, type checks for every re-exported type, a trait
object (`dyn Approver`), and a constructed `Divergence`.

## LoopInit (P-05 §14)

`driver/step.rs` now has `pub(crate) struct LoopInit<'a>` with the same 25
fields as `Loop`, and `Loop::new(init: LoopInit<'a>) -> Loop` which moves
them one-to-one (destructuring `let`, no clones). All eight construction
sites use it — the three production loops (`run` in `driver.rs`, `audit`
in `replay/audit.rs`, `resume` in `replay/resume.rs`) and the five test
loops (`tests.rs` twice, `context_tests.rs`, `presubmit_tests.rs` twice).
P-13/P-17 add a loop field in three places (struct, init struct, `new`)
instead of eight.

## Notes for reviewers / later slices

- Visibility was widened only where a moved item is used across the new
  module edges (and always at most to `pub(crate)`): `Flow`, `is_read`,
  `decided`, `denied_text`, `create_run`, `todo_for`, `digest_at`,
  `recorded`, `recorded_facts`, `check_wall_conditions`,
  `expected_inputs`, `check_header`, `diverge`, `UNREADABLE`,
  `attempts_desc`, `has_header`, plus the item-level `pub(crate)` on
  moved structs/fields. Nothing became `pub`.
- `NOT_SAMPLED` stayed private to `replay/audit.rs` (only `audit` uses
  it); the plan draft said `pub(crate)` but widening for no user would
  draw a dead-code warning.
- `driver.rs`'s `pub(crate) use` re-export block is a deliberate bridge:
  it keeps `replay.rs`'s original flat import list (and the test files'
  imports) textually unchanged. P-13/P-17 may prefer direct
  `crate::driver::step::...` paths later.
- Only one non-test path outside the two files was touched:
  `tests.rs`'s `crate::replay::check_wall_conditions` became
  `crate::replay::compare::check_wall_conditions` (`check_wall_conditions`
  is `pub(crate)`, so this is a crate-internal path only).
