# P-24 — Repo-map-lite outline (`harness.fs.outline`, deterministic regex symbol extraction)

## What landed

- `crates/harness-manifest/src/builtin/fs_outline.rs` (new fragment) —
  `harness.fs.outline` in manifest order after `harness.fs.list`:
  read / operational / own / none, `content: third_party` (like the other
  read tools), schema `{path?: string ≤ 4096, kind?: string ≤ 16}`,
  `additionalProperties: false`, no `required` (both arguments optional).
  The built-in manifest sha moved to
  `c16d6a80a24043ce0813de9f2619d8bc3bcd49ea8d8f0d4f7b198ab81fda7d38`
  (pinned in `harness-manifest`'s `builtin_manifest_bytes_unchanged`; a
  journal-header manifest change is expected and deliberate, per the P-02
  precedent).
- `crates/harness-policy`: `OUTLINE_ID` in the registration table after
  `harness.fs.list` (now 11 tools), `OUTLINE_ID` added to
  `DEFAULT_DENY_CAPABILITIES` (8 × 10 = 80 default deny rules; edit
  indices shift by 10, per the stable capability-major × glob order) and
  to `UserPolicy::denied_globs`' `SURFACING` list (the outline is
  content-surfacing, so it walks with the same skip globs).
- `crates/harness-tools/src/outline.rs` (new module) — the extractor and
  the tool:
  - Language by extension: Rust (`.rs`), Python (`.py`, `.pyi`), JS
    (`.js/.mjs/.cjs/.jsx`), TS (`.ts/.mts/.cts/.tsx`), Go (`.go`), C
    family (`.c/.h/.cc/.cpp/.cxx/.hpp/.hh`), Markdown (`.md/.markdown`).
  - Kinds: Rust `fn` (with `pub`, `pub(...)`, `const`, `async`,
    `unsafe`, `extern "..."` prefixes), `struct`, `enum`, `trait`,
    `impl` (whole trimmed line); Python `def` (incl. `async def`),
    `class`; JS/TS exported declarations only (`function` incl.
    `default`/`abstract`/`async`/`*`, `class`, `const`/`let`/`var`,
    `interface`, `type`, `enum`); Go `func` (with optional receiver),
    `type`; C family `function` (column-0 line with an argument list, no
    trailing `;`, not a control keyword or typedef) and
    `struct`/`enum`/`union` tags; Markdown headings `^#{1,6}(\s|$)`.
  - Comment lines never match (`//`, `/*`, `*`; `#` for Python and the C
    family's preprocessor). Indented Rust `fn`s match, so trait and impl
    methods appear in the outline (a map shows methods).
  - `kind` filter: case-insensitive; `fn`/`func`/`function` are one kind
    spelled per language, `const` covers `let`/`var`. An unknown kind
    value selects nothing: an empty outline, not an error.
  - Bounds: at most `OUTLINE_MAX_ENTRIES` = 200 symbols shown (no user
    cap argument), signatures cut at 160 bytes with `…`; the cap lands
    on the global order (component-wise path order — the walk's own —
    then line number), so a sorted-later file is not hidden. The result
    is additionally cut at `RESULT_MAX_BYTES` by `finish()` as usual.
  - Sort: component-wise path order (so `a/b` before `a-c` although
    `-` < `/`), then line; deterministic SHA-256 of the shown entries in
    the head, so two calls over the same bytes agree byte for byte.
  - File mode: unknown extension → new error code `NO_OUTLINE` (23);
    non-UTF-8 → `NOT_TEXT`; over `SEARCH_FILE_MAX_BYTES` (1 MiB) →
    `TOO_LARGE`; a denied path arg is refused by the policy first (the
    tool's checks are defence in depth).
  - Directory mode: the same confined walk as search/glob — no symlink
    followed or entered, `.git` below the start skipped (counted),
    denied paths neither entered nor matched (counted), files over 1
    MiB or non-UTF-8 skipped (counted), bounded in entries, depth and
    deadline. The foot is the search's style: denied count, skip count,
    symlinks, `.git`s, walk stopped.
  - No `ReadRecord`: the outline is not a full read, and `read_sha256`
    feeds only the edit-anchoring read log (search/glob/list emit none
    either).
- `crates/harness-tools`: `OUTLINE` const, `serves` + invoke arm, new
  code `NO_OUTLINE = 23`, dispatch table entry (workspace read tools),
  `OUTLINE_MAX_ENTRIES` re-exported.
- `crates/harness-run/src/driver/tools.rs`: `is_read` includes
  `harness.fs.outline`, so a repeated outline on an unchanged workspace
  gets the repeat-read notice.

## Ambiguity readings

- "default 200 lines" → a fixed 200-entry cap (no `limit` argument); the
  model narrows with `path`/`kind`.
- `kind` over symbol kinds, case-insensitive, unknown value = 0 entries
  (a filter for symbols that are not there is an empty result, not an
  error), matching the schema's plain `string` typing.
- File-mode errors keep the read tools' own codes (`NOT_TEXT`,
  `TOO_LARGE`); only "no language for this extension" is new (`NO_OUTLINE`).
- No context-format bump: the manifest sha in journal headers changes
  (deliberate, P-02 precedent) but the rendered-context format does not
  (the H2e precedent: a new read-class tool did not bump it).
- P-33 can reuse `outline.rs`'s `Extractor`/`lang_of` when it needs the
  same extraction outside the tool.
