## Stub diff summary (line by line)

The only change to `fileop_stub.rs` after `272666e` is the rewording of
one test comment (commit `db368cd`, lines 119-123); no executable line
moved:

- old: three lines reading "The pin's absolute-path scan reads this file
  raw for `"/…"`; a double quote is the only way to form one, so the
  stub (and this file) hold none. purity.sh re-checks both facts
  mechanically."
- new: four lines stating the same fact without the quoted slash — "The
  pin's absolute-path scan reads this file raw for a double quote
  followed by a slash: a double quote is the only way to form an
  absolute-path literal, so the stub (and this file) hold none.
  purity.sh re-checks both facts mechanically."

The reword exists because the new raw-view scan would have tripped over
the old comment's own `"/…"` spelling. The stub's perl text (start
canary, `kill(0,$pp)` per-pass check, op loop, `O_NOFOLLOW`,
`Digest::SHA`, link+unlink move, directory fsync) is untouched, and the
existing stub unit tests still pass.

## Observed flake (pre-existing, P-36b, not touched here)

Two earlier loaded runs (one full `--workspace`, one
`-p harness-sandbox`) failed
`ft_bg_parent_sigkill_sweeps_the_domain`
(`tests/conformance_bg_macos.rs:362`): the fake harness was SIGKILLed
and reaped as designed, but the stub exited with `ppid=1` leaving the bg
program and its setsid grandchild alive past the test's 15 s bound.
The test passes reliably when the binary runs alone or serially,
including in the final green full-workspace run above. The machinery
already reaps the harness instantly via a reaper thread precisely to
avoid the zombie-canary trap, so the residual race is most plausibly
the sweep's per-pass canary `kill(0,$pp)` hitting a reused harness pid
on a loaded host (the known R-1 pid-reuse family, design §17) or the
sweep's kill-scan being starved past its deadline. Out of this slice's
scope: not weakened, not fixed, flagged for a P-36b follow-up.

## Notes and design questions

- The fileop pin block sits directly after the confine pin block with
  the same shape and comment discipline (slice id, date, one sentence),
  per design note §13; the selftest anchors
  (`Command::new("/bin/kill")`, the canary and acceptance lines) are
  byte-identical to before.
- Design question for the manager: should a future slice harden the
  P-36b sweep against harness-pid reuse (e.g. canary keyed on the
  harness's start time or a pipe EOF as the sole death signal) — the
  current per-pass `kill(0,$pp)` accepts a hit on a reused pid as a
  "canary" and skips the sweep, which is the only flake signature
  observed on this host.
- Design question: the purity rule bans absolute-path literals in the
  raw file, and the stub needs none; if a future operation ever needs a
  system path (it should not — everything is workspace-relative by
  policy), the pin would have to be consciously renegotiated, which is
  the intended friction.
