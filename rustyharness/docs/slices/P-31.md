# P-31 — Hosted model via loopback proxy: declaration, disclosure rule, cost budget

Branch `w/P-31` (worktree). No new dependencies; `Cargo.lock` untouched.
Crates: `harness-model-core` (profile), `harness-run` (planning refusals,
header, meter pricing), `harness-cli` (task cost budget, usage footer,
banner, `/status`, `/usage`).

## What was built

- **Profile** (`harness-model-core/src/profile.rs`): two optional v1
  fields, `upstream: "hosted"` and
  `price_table{in_micro_per_ktok,out_micro_per_ktok}` (strict, u64). Both
  join the content digest ONLY when the profile is hosted, so every local
  profile — every profile written before P-31 — keeps its digest and its
  `profile check` stamp (the pinned digests in the tests still hold).
  Fail closed: `upstream` accepts only the value `hosted` (any other
  string is an unknown variant → shape error); an explicit `null` for
  either field is refused; `price_table` without `upstream: "hosted"` is
  refused (`NotInThisBuild`); the old `price` field stays refused. New
  accessors: `Profile::hosted()` and `Profile::pricing()` — the table
  converted to `harness_core::Pricing` (micro-USD PER TOKEN, i.e.
  kilo-token prices divided by 1000 with integer division; a price that is
  not a whole number of micro-USD per token floors, never rounds up — the
  budget is a ceiling and the audit recomputes identically).
- **Planning refusals** (`harness-run/src/driver/plan.rs`,
  `RunRefused::Hosted(&'static str)`, outcome `CouldNotRun`): checked at
  the top of `plan()`, so a live run, a session, a research session, a
  resume and an audit replay all refuse alike. A hosted run (1) without a
  price table refuses to start (§2.4, N-7) and (2) refuses any grant whose
  capability's sensitivity is at or above personal (Q-2: the context —
  task, rules, every observation — leaves the machine through the proxy).
  The sensitivity rule sits behind the pure `hosted_takes_no_personal`
  seam.
- **Header** (`driver/header.rs` + `replay/compare.rs`): a hosted run's
  journal header carries `endpoint_class: "loopback-proxy-hosted"`. It is
  a header input (`HEADER_INPUT_KEYS` now 22), recomputed by
  `expected_inputs` and compared by audit and resume; absent for a local
  profile, so every journal written before P-31 reads exactly as before
  (Q-3).
- **Cost budget** (`driver.rs` `new_meter`/`new_meter_resumed` gained a
  `pricing: Option<Pricing>` parameter; `run`, `run_session`,
  `run_research`, audit and resume pass `profile.pricing()`): the meter's
  existing `Cost` dimension now charges in production — tokens × price,
  saturating, from `ModelReplied.usage` (or the byte estimate when the
  server reports none), latching `Budget(Cost)`. A LOCAL run's pricing is
  `None` and its cost stays 0. The cost LIMIT is user-set: the task file's
  `budget` section gained `cost_micros` (1 to 10¹⁵ micro-USD; header
  input, already compared). Default limits keep `cost_micros: 0`, which is
  "no budget in use" for a local model and an immediate stop for a priced
  hosted one — fail closed: a hosted run needs a budget the user set.
- **Disclosure**: `run_session`/`run_research`'s banner and the ACP banner
  print `context is sent to a hosted provider` while the profile is
  hosted; `/status` appends the same clause; `/usage` and the
  `run --output stream-json` footer gain `cost_micros` (JSON, only when
  the profile is priced) and `, cost $X.XXXXXX` in the words — computed
  from the tokens the servers REPORTED (`ModelReplied.usage`), saturating;
  replies without usage are meter-estimated for the budget but contribute
  nothing to the footer (the footer claims no estimate).

## Caveats / manager questions

- **Q-2's end-to-end refusal is unreachable in this build**: no admitted
  registry can carry a capability at personal sensitivity (Signed tiers
  gate on H4's signature verification; Pinned tiers refuse sensitivity
  above operational). The rule is enforced in `plan()` from day one and
  tested at its pure seam (`hosted_takes_no_personal`); when H4 opens the
  gate, `tests/hosted.rs` should gain the registry-with-personal-grant
  case (a sketch of that fixture lives in this slice's history).
- **Sessions have no cost-budget surface**: `SessionConfig::defaults`
  keeps `cost_micros: 0`, so a hosted CHAT stops at the first charge
  unless a budget is added somewhere (no CLI flag exists today; the task
  file's `budget.cost_micros` covers batch `run`). Fail closed, but a
  manager question: where should a session's cost budget come from
  (P-05/P-17 territory)?
- Rounding: kilo-token prices floor to whole micro-USD per token
  (`pricing()`), documented on the accessor; the audit recomputes the same
  way, so no divergence is possible from the flooring itself.
- The footer's cost covers only server-reported tokens; the meter's budget
  covers estimates too. The two can differ slightly for servers that do
  not report usage; the footer says nothing it cannot back from the
  journal.
