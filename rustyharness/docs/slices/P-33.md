# P-33 — Deterministic conversation ledger, repo-map block, terse tool docs (rh-context/9)

## What landed

- `SESSION_CONTEXT_FORMAT` bumped `rh-context/8` → `rh-context/9`
  (`crates/harness-model-core/src/context.rs`). Batch stays `rh-context/5`,
  research stays `rh-research/2` (`context_fmt9_only_session_mode` pins all
  three). The bump refuses old session journals at the header's
  `context_format` key by design: audit them with the build that wrote
  them.
- **Ledger** (session context, after the project-notes block, before the
  repo map and the approved plan): a harness-written, deterministic block
  — `Ledger (kept by the harness; deterministic, from the journal):` —
  with the checklist state, the files-touched table (`path — n edit(s),
  last sha256 …` / `last deleted it`), the commands run (`argv — end`)
  and the events (`mode: plan|build`, `restored n file(s) to the tree of
  step s`). No model-written summary (Q-9 default stands); it replaces
  nothing. Cut to `LEDGER_SHARE_PERCENT` (4%) of the window on whole-line
  boundaries keeping the NEWEST lines (entries are oldest-first), heading
  always kept, with a `The ledger was cut to k of n lines …` notice. An
  empty ledger renders nothing, so a session's first steps (and old
  journals' shapes) are unchanged.
- **Repo map** (optional, session coding only): an outline of the session's
  recently touched files, extracted with the P-24 extractor exposed as the
  pure `harness_tools::outline::file_outline_text(rel, text)`. Ranked by
  (last-edit step desc, edit count desc, path asc) — journal-derived
  recency, not mtime, because only the journal is recomputable. At most 8
  files, each ≤ 1 MiB, UTF-8 only, no symlinks, plain-relative paths only
  (re-checked even though `EditApplied` already confined them). Rendered
  as a digest-named `repo-map` block, cut to `REPO_MAP_SHARE_PERCENT`
  (8%) with a notice; the digest covers the full text.
- **Journal/replay**: the `ContextBuilt` record of a coding session gains
  an optional `repo_map` untrusted workspace payload, written exactly
  when the map is in the request. `replay/feed` parses it (workspace
  source, UTF-8 text, by step); an audit and a resume's catch-up RE-FEED
  it (an audit never reads the workspace) and write the identical payload
  back — `repo_map_recomputed_identically_by_audit` audits clean end to
  end. The text is digest-covered through the context digest either way,
  and the journal hash chain covers the payload. A research session or a
  batch run never carries a map; a replayed one ignores any recorded map,
  so such a journal diverges at its `ContextBuilt` (fail closed).
- **Ledger state in the loop** (always starts empty, re-derived by
  re-driving like the plan state): commands captured at the exec result
  (argv from the parsed call, end from the `exec` record — identical in a
  replay); events pushed at `/plan`, `/build` and `journal_restored` (one
  place, so live runs and audit recomputes agree).
- **Terse tool docs** (P-53 landed the mechanism; this slice pins it):
  `terse_docs_reduce_tool_block_bytes` (terse requests are strictly
  smaller) and `full_docs_digest_unchanged` (an explicit `"full"` profile
  renders the default's bytes, nonces aside — a nonce is drawn per run;
  only a terse run stamps the header's `tool_docs` key).

## Decisions / notes

- Ledger todo lines are the harness's rendering of state it applied via
  `TodoList::apply` (one `- [status] text` line per item) — ledger
  material, not a model-written summary.
- The ledger's files table comes from the restore log's edit marks
  (`touched_files`, path order); the repo map ranks the same marks by
  recency.
- `cut_tail` drops a single line longer than the whole remaining share
  (fail closed); the notice still names the cut. With a cap under the
  heading's length the block is omitted and only the notice shows.
- The format bump needs no compatibility code: `check_header` refuses a
  foreign `context_format` by name.
