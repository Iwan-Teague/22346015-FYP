# P-16 — Edit diff preview renderer (`harness_core::diff` + `EditTools::preview`)

## What landed

- `crates/harness-core/src/diff.rs` — the pure, bounded unified line diff:
  - `unified(old, new, context, max_lines) -> String`: the classic unified
    format (`@@ -a,b +c,d @@` hunk headers with the `,1` omitted, a
    ` `/`-`/`+` body, GNU `\ No newline at end of file` markers), hunks
    merged when their gap is at most `2*context`. Identical inputs give an
    empty string.
  - Line endings are data: lines split on `\n` only, every `\r` stays on
    its line, so CRLF text passes through byte-for-byte and a CRLF-vs-LF
    difference shows as a change on every line it touches.
  - Determinism and bounds: an LCS dynamic program over the stripped
    middle, capped at `DP_MAX_CELLS` (2M) — past the cap it degrades to a
    plain delete-all/add-all block, worse diffs, never wrong ones; output
    capped at `max_lines`, a cut ending with `[N lines cut]` (`N` = lines
    not shown; the marker is never dropped, `max_lines = 0` shows the
    marker alone). No clock, no hashing, no randomness.
  - `DEFAULT_CONTEXT = 3`, `DEFAULT_MAX_LINES = 200` for callers without a
    stronger opinion.
- `crates/harness-tools/src/edit.rs`:
  - The apply path's pure halves are factored out so a preview can only
    show what an apply would write: `plan_replace` / `plan_multi` /
    `plan_write_overwrite` (match checks, line-ending conversion, splice,
    caps, no-op refusal — no I/O), `check_replace_args` /
    `check_multi_edits` (the pre-resolve argument checks), and
    `parse_replace_args` / `parse_multi_args` / `parse_write_args` (the
    same BAD_ARGS parse the tool calls run). `replace`/`multi`/`write`
    keep their exact check order and behaviour.
  - `EditTools::preview(&Call, &ReadLog) -> Result<String, PreviewRefused>`:
    plans the edit in memory and renders `--- a/<path>` / `+++ b/<path>`
    (a create diffs against the empty file and is headed `--- /dev/null`)
    plus `harness_core::diff::unified` at its defaults, sanitised through
    `harness_core::display::sanitize_for_terminal(.., DisplayMode::Block)`
    (P-04). Nothing is written, nothing is journalled, no directory is
    created; deterministic, no deadline (a preview is not an invoke).
  - `PreviewRefused`: `NotEdit` (not an edit capability), `BadArgs` (the
    tool parse's message), `Edit(EditError)` (the apply path's own
    pre-write refusal).
  - Write's create regime is previewed without mutation: the content cap,
    then `check_new_parents`, a read-only mirror of `create_parents`
    (existing components must be real directories, symlinks refused, at
    most `WRITE_MAX_NEW_DIRS` missing). A missing intermediate that resolve
    already fails with `ENOTDIR` (a file where a directory belongs)
    surfaces as the same `Io` error apply reports.

## Ambiguity resolution (fail-closed)

The card writes `EditTools::preview(&Call)`, but one required test
(`preview_refuses_stale_read_like_apply`) is impossible without the run's
read log: the stale-read check IS the anchor check. Preview therefore takes
`(&Call, &ReadLog)` — the same anchor `replace`/`multi`/`write` take — and
refuses exactly as they refuse.

## Not loop-visible

A preview enters no journal record and changes no context: it renders text
for the approval/inspection UI before a decision, and the decision (not the
preview) is what the loop sees. ROADMAP §4.1's audit-replay requirements
(journal record, replay recomputation, audit-clean test, context-format
bump) therefore do not apply to this slice; the preview is recomputable by
construction from the call, the file and the read log.

## Tests

- `crates/harness-core/src/diff.rs`: `diff_identical_is_empty`,
  `diff_single_line_change`, `diff_crlf_preserved_marked` (CRLF preserved;
  CRLF-vs-LF is a change), `diff_bounded_marks_cut` (line cap, marker never
  dropped, cap 0 = marker alone), `diff_deterministic`,
  `diff_marks_missing_final_newline` (no-newline markers, create and
  delete-all headers).
- `crates/harness-tools/src/edit.rs`: `preview_replace_matches_applied_result`
  (the preview is what applying really produces, apply verified by digest),
  `preview_does_not_modify_file` (bytes and directory unchanged),
  `preview_refuses_stale_read_like_apply` (`NeverRead` and `Changed` on
  both paths), `preview_write_create_heads_dev_null_and_refuses_like_apply`
  (`/dev/null` header, nothing created, `TooManyDirs`, the ENOTDIR case
  agreeing with apply), `preview_refuses_a_non_edit_call`.
- `cargo test --locked -p harness-core -p harness-tools`: all green;
  `cargo fmt --all --check`, `cargo clippy --locked --workspace
