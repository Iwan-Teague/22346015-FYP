# P-38d — Child run construction (harness-run)

Implements the construction pieces of docs/slices/P-38-subagents.md §2.1–§2.3
and §3: `harness-run/src/delegate.rs` (new module), the child header inputs,
and the `prepare` refusals. Admission, the loop's `delegate` branch and the
`ChildRun` framing are P-38e; child audit replay is P-38f.

## Deviations (fail-closed readings, noted per the card)

1. **`child.brief` is a digest, and the brief travels as a claim.** The
   design names `child: Obj { brief: UntrustedBlob, ... }`, but a
   `Trusted` header field cannot hold an `UntrustedBlob` (the journal
   mints those only in records/claims), so the `child` object carries
   `brief: Digest` (SHA-256 of the brief's exact bytes) and the brief text
   travels as the top-level untrusted claim `child_brief`
   (source tool `harness.task.delegate`), exactly like the `claimed_*`
   fields. Claims are not in `HEADER_INPUT_KEYS`, so audits compare only
   the digest — the binding the design wants.
2. **`ChildCtx.timeouts: &RunConfig`.** §2.2 says the child inherits "the
   parent's timeouts", but §2.1 lists no carrier; the ctx holds a `&RunConfig`
   and the child's `RunConfig` copies the timeouts with its own limits.
3. **`ChildCtx.live` is enforced.** `run_child` refuses `live == false`
   (a replay constructs no children); `admitted` is carried (with a scoped
   `allow(dead_code)`, to be removed when P-38e reads it) so the shape is
   fixed now. The module-level `dead_code` allowance in `delegate.rs` goes
   when the delegate branch lands.
4. **`mode` mismatch text** is "the run's mode (batch, session or child)
   differs from the recorded header" — the design's list of modes, not a
   behavioural change.
5. The link is cross-checked against the ctx (`run`/`attempt` must agree)
   before anything is created.
