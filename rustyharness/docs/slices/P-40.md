# P-40 — `/diff` (REPL) and `rustyharness review --run ID`

Branch `w/P-40` (worktree). No new dependencies; no `Cargo.lock` change.
Library surface unchanged: this slice only adds a read-only consumer in
`harness-cli` (`cmd_review.rs`) and wires the `chat` REPL's `/diff` to it.

## What was built

- **`review` verb** (`crates/harness-cli/src/cmd_review.rs`; not a gate
  child — plain exit codes, human lines on stderr):
  `rustyharness review --run <run-id> --workspace <dir> [--state-root <dir>]`
  (`--state-root` flag > config > default, P-07, like `events`). Exit 0
  whenever the review was produced (flags and all), 2 usage, 4 when the
  run, its journal, its blobs or the workspace cannot be read.
- **The diff is computed from the journal, never from `git`**: the
  `EditApplied` records (P-22) cite the file's bytes before and after as
  content-addressed blobs. Review collects them in journal order and, per
  path, keeps the FIRST pre-image (`before_blob`, or the empty bytes when
  the first record is a create) and the LATEST after-image. The latest
  attempt alone is enough for a whole session: a resume re-feeds its prior
  edits as `EditApplied` records in the new attempt (driver/step.rs
  `fed_tree` path).
- **Tamper check on cited blobs** (`review_detects_blob_tamper`): the
  journal's chain verifier checks untrusted payload homes (sha256/len of
  inline and blob carriers) but NOT trusted `Digest` citations, so review
  itself fetches every cited `before_blob`/`after_blob` from the attempt's
  `blobs/` and re-hashes: a blob's name is its content's SHA-256, so a
  swap or an in-place edit is caught. The shape rules the loop writes are
  enforced too (`before_blob` present exactly when `before` is and naming
  the same bytes; `after_blob == after`) — anything else is "not the shape
  the loop writes" (exit 4, fail-closed). A flagged path shows the problem
  and NO diff is rendered from tampered bytes; other files and the chain
  head still show.
- **Workspace check** (`review_flags_out_of_band_change`): each path is
  validated with `harness_policy::workspace_path` and resolved by a
  symlink-refusing component walk (the same rule as the edit tools'
  resolution: no symlinked component, intermediates must be directories,
  the file a regular file), then re-digested against the last
  after-digest. Equal → `clean`; different → `changed outside the
  harness`; missing → `missing from the workspace`. The journal diff is
  still shown in the non-clean cases: what the session did is evidence,
  the status line is what changed since.
- **Diff rendering** uses `harness_core::diff::unified` at the P-16
  defaults (context 3, 200-line cut), with the edit tools' header style
  (`--- /dev/null` for a create, else `--- a/<path>`; always
  `+++ b/<path>`). A non-UTF-8 side shows byte counts instead of a text
  diff. Output ends with `chain head <hex>` (§7.1 "Anchoring") after the
  per-file lines, preceded by the run/attempt line (complete or torn tail)
  and the workspace.
- **`/diff` in the `chat` REPL**: the same core over the live session's
  attempt directory (`st.attempt_dir`) and workspace (`st.workspace`);
  `no journal yet` before the first attempt exists. Nothing about a review
  is loop-visible: no journal record, no context change, no
  `context_format` bump, and no audit-clean requirement — it is a
  read-only consumer, like `events`.
- **USAGE text** gained the `review` line and its golden test moved with
  it (both sides, not a weakening). A session with no `EditApplied`
  records says `no file changes in this session`
  (`review_empty_session_message`).

## Design choices worth recording

- The run's recorded workspace path is convenience-not-evidence (the
  journal header does not carry it; `runs/<id>/inputs/bundle.json` is a
  convenience copy), so `review` REQUIRES an explicit `--workspace` — the
  person at the terminal states what "the workspace" is; the REPL passes
  the session's own.
- Review of a live (uncommitted) journal is allowed and meaningful: the
  reader accepts a torn tail and reports it (`torn tail` in the header
  line).

## Named tests (all unit tests in `cmd_review.rs`, over real temp directories with journals written by the real `JournalWriter`)

- `review_diff_matches_workspace_changes` — create + edit journalled, the
  workspace holds the final bytes: `a.txt: clean`, `--- /dev/null`,
  `+++ b/a.txt`, the `+two` line, exit 0.
- `review_flags_out_of_band_change` — the workspace file edited by hand
  after the session: the status line says so, the journal diff still
  shows.
- `review_detects_blob_tamper` — the last after-image's blob rewritten in
  place under its content-addressed name: flagged ("does not hash to its
  digest"), no diff rendered from tampered bytes, chain head still shown.
- `review_includes_chain_head` — the printed `chain head <hex>` equals the
  journal reader's own head.
- `review_empty_session_message` — a journal with no edits: the message,
  exit 0, chain head still named.

## Residuals and readings

- The workspace check reads the file whole (`fs::read`); workspaces here
  are small text files (the edit tools' domain). A huge file would be slow,
  not wrong.
- A path the journal holds that the policy's lexical rules would refuse
  (only possible in a hand-forged journal) is flagged `path refused`,
  not silently skipped.
- Review flags but does not fail: exit 0 with flags on stderr is the
  contract (the human reads; nothing here writes).
