# P-36h — journal: `BgStopped`, `OrphanCheck`, the `bg` record

Implements §10 (journal) of `docs/slices/P-36-background-processes.md` for
the record shapes and the two new kinds. Deps: P-10. Crates:
`harness-journal`, `harness-run` (`driver/tools.rs` record fns and their
call sites only). No new dependencies.

## Journal (harness-journal)

- `EventKind`/`KINDS` gain `BgStopped` and `OrphanCheck` (H-E's last
  additions, done here once). Both are `needs_fsync()`: they are
  measurements the audit re-feeds, and resume keys on the stops. The
  canonical field lists are documented on the enum (§10.1 verbatim:
  `BgStopped` = `id`, `reason`, `end`, `cleanup`, `out_total`, `err_total`,
  `out_sha`, `err_sha`; `OrphanCheck` = `markers`, `clear`, `suspect`,
  `action`).
- `event.rs` needed no change: bodies are open-ended (`Event::field`), the
  kind is the only closed list.

## harness-run (`driver/tools.rs`)

- `bg_fields`/`parse_bg` beside `exec_fields`/`parse_exec`, with the four
  op shapes of §10.2: `start` (`ready` present exactly when asked),
  `read` (`end`/`cleanup` together or not at all), `list`, `stop` (with
  the two whole-stream digests). Both go through the exact-shape guard:
  a body reads back only when it is byte for byte what the writer would
  write. The types (`BgRecord` and friends) are `pub(crate)`; the tools
  that produce the records arrive with P-36i, so the items carry
  `#[cfg_attr(not(test), allow(dead_code))]` until then (the
  `harness-sandbox` precedent).
- Exec record: `exec_fields` now takes `connect: &[u16]`; the field is
  written only when non-empty, after the cleanup fields and before the
  byte counts, so every journal from a build before background processes
  encodes the identical body (test pins the pre-P-36h field list by
  hand). `parse_exec` accepts `connect` only as the exact shape (an
  injected `connect: []` is refused). Call sites (`driver/step.rs`,
  `presubmit.rs`) pass `&[]`: no bg process can exist yet.
- `replay/feed.rs`: `BgStopped`/`OrphanCheck` are refused by `recorded()`
  like the other reserved names until P-36k re-feeds them — nothing
  writes them before the tools and the stop-all exist, and a record this
  loop never writes must read as a divergence, not as silence.

## Not in this slice (and why)

- Header `bg`/`ports`/`file_ops` objects: they are pass-in header fields
  (`Header::field`); no code can grant bg tools or ports before P-36g/
  P-36i, so they are absent in every journal this build can write and
  old header digests are unchanged by construction. The writing slices
  add them when the grants exist.
- Audit re-feed of the two kinds and the `bg` object: P-36k (the card's
  dependency chain stops at "the record shapes"; `feed.rs` keeps them
  refused on purpose, tested by the existing round-trip and feed tests).

## Doubts / notes for the manager

- The `allow(dead_code)` gate is the one judgement call: the record
  shapes are written and pinned by tests now but produced only from
  P-36i. Fail-closed alternative would have been to defer the file
  wholesale, but the card names the fns for this slice.
- `BgStopped.end` reuses the exec record's end shape (§10.1 "as
  exec_fields' end"), including the `guard` field the exec record writes
  for `timed_out`/`process_limit`/`exec_failed`; §10.1 does not name
  `guard` explicitly. Kept (same helper, one shape), noted here.
