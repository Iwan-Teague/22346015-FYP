# P-15 — `events` projection, `run --output stream-json`, usage footer

Branch `w-P-15` (worktree). No new dependencies; `Cargo.lock` unchanged
except nothing (no version bumps). Library APIs: `harness-journal` gained a
tail reader (`JournalTail`/`Poll`) and `Verified::line_bytes`; `harness-cli`
gained the `events` verb (`cmd_events.rs`) and the usage module (`usage.rs`);
`run`/`resume` accept `--output stream-json`.

## What was built

- **Tail reader** (`crates/harness-journal/src/tail.rs`): `JournalTail::open`
  binds to an `attempt-<n>` directory with the same checks as
  `JournalReader::open` (real dir, real non-symlink `journal.jsonl` and
  `blobs/`). `poll()` re-reads and re-verifies the WHOLE file with the same
  `verify`, so a record is only ever reported once it verifies — a torn
  final line is never emitted (it appears only once its newline arrives).
  Fail-closed: any `Broken`, a shrunken file (edit/replace, checked before
  verification), a journal whose attempt differs from the directory, or a
  symlink ends the tail with `ReadError`. `Poll{new_records, verified}`
  carries the records no earlier poll reported and the latest `Verified`
  (whose `is_complete()` says the run committed). The full re-read keeps the
  code simple and honest; journals are small (§7.1).
- **Line re-encoding**: `Verified::line_bytes(i)` rebuilds record `i`'s
  canonical line bytes (no trailing newline) via `RecordFields::encode`,
  reconstructing `prev` from the chain (`GENESIS` for seq 0) and
  `run`/`attempt` from the header. The reader only accepts byte-exact
  canonical lines, so the re-encoding IS the journal's own line (a
  `debug_assert` on the hash cross-checks).
- **`events` verb** (`crates/harness-cli/src/cmd_events.rs`; not a gate
  child — plain exit codes, human lines on stderr):
  `rustyharness events --run <run-id> [--state-root <dir>] [--format ndjson]
  [--follow]`. Options: `--run` required (a `RunId`), `--format` only value
  `ndjson` (absent = ndjson), `--state-root` flag > config > default
  (`config::state_root`, P-07), `--follow` a valueless flag (new
  `options_with_flags` parser beside `options`). Exit 0 records shown, 2
  usage, 4 the run or its journal cannot be read (no run, broken journal, a
  `--follow` journal that ends unreadable, or — defensively — a journal that
  names another run). Stdout: first line `{"schema":"rh-events/1"}`, then
  one line per record, byte-for-byte the journal's canonical line.
  `--follow` prints the schema + current records, then polls every 50 ms
  until `is_complete()`, emitting only new records.
- **Untrusted payloads** are shown in their journal payload home (§7.1):
  <= 4 KiB inline and escaped — the journal's OWN sanitisation (`escape`
  neutralises control, zero-width and bidi characters), so nothing here can
  be an injection sink — and larger ones as `blobs/<sha256>` references with
  the digest. The projection is verbatim: it adds nothing and hides nothing
  (the brief's "inline <= 4 KiB sanitised, else blob ref + digest" is the
  payload home itself; no extra transformation).
- **`run --output stream-json`** (and `resume`, same code path): the only
  accepted value; anything else is a usage error through the report path
  (exit 2, last line still the GateReport) BEFORE anything runs. After a run
  that started, the stdout stream is: the schema line, one line per record,
  `usage {...}`, then `chain_head <hex>` and the GateReport (the last line,
  unchanged contract). An attempt journal that cannot be read does not
  change the run's report or exit code — it is noted on stderr and the
  stream is simply absent (honest note, §7.7 words on stderr).
- **Usage footer** (`crates/harness-cli/src/usage.rs`), computed from the
  verified journal, display only: `steps` (max step), `model_calls` (count
  of `ModelRequested`), `tokens.in/out` (sums of `ModelReplied.usage`),
  `wall_ms` (last − first `t_mono_ms`, saturating), `tools` (ToolStarted
  counts by capability id). `tokens.cached` appears only when some reply
  carried a `claimed_stats` claim; it is the server's own claim
  (OpenAI `usage.prompt_tokens_details.cached_tokens` or llama.cpp
  `timings.cache_n`) read from the untrusted payload's inline text — a blob
  claim adds nothing, an unparseable claim is dropped (fail-open for
  display only). JSON: `{"model_calls":N,"steps":N,"tokens":{...},"tools":{...},"wall_ms":N}`
  (BTreeMap-sorted). Also said in words on stderr.
- **USAGE text** updated (events line, `[--output stream-json]`) and its
  golden test with it (both sides, not a weakening).

## Named tests (all in `crates/harness-cli/tests/cli.rs` unless noted)

- `events_ndjson_one_line_per_record` — schema first, one object per record,
  all ten record keys, `RunStarted` first/`RunStopped` last, count matches
  the journal on disk.
- `events_chain_verifiable_from_stream` — the hash chain recomputed from
  the stream alone: `prev` links and `sha256(prev_raw || canonical)`
  verified per record; the stream's head equals the run's `chain_head` line.
- `events_follow_sees_new_records` — a hand-built live journal (torn second
  line), a `--follow` tail on a thread writing into a shared buffer; the
  first record appears, the commit (`RunStopped`) is seen after the journal
  completes, exit 0, every record exactly once.
- `events_torn_tail_not_emitted` — a torn final line (no follow): only the
  verified prefix is shown, exit 0.
- `events_untrusted_payload_sanitised` — model text carrying zero-width and
  bidi characters reaches the stream only in the journal's escaped spelling;
  no raw invisible character in the stream bytes.
- `usage_matches_budget_charged` — a real run against a mock reporting
  `usage {prompt_tokens:100, completion_tokens:10, prompt_tokens_details:
  {cached_tokens:64}}`: the footer says 2 model calls, in 200 / out 20 /
  cached 128 (the server's claim), steps 2, tools by capability; cross-checked
  against the journal's own `ModelRequested`/`ToolStarted` counts; the words
  on stderr.
- `final_stdout_line_still_gatereport` — with `--output stream-json` the
  last stdout line is still the GateReport (`gate` id, outcome), preceded by
  `chain_head`, with the `usage` line before it and the schema line first.
- `stream_json_run_exit_codes_unchanged` — plain run vs stream-json run:
  same exit code (5), same verdict, marker still absent; `--output fancy`
  is a usage error (exit 2) through the report path, before anything runs.

(`harness-journal` also gained unit tests for the tail: new records only,
completion detection, torn lines never emitted, broken/shrunk refusal,
directory binding, and `line_bytes` round-tripping to the file's own bytes.)

## Residuals and readings

- Budget: `BudgetCharged` records are standing-condition enter/exit events
  (80%), not per-step charges, so the footer's numbers are the loop facts
  (steps, model calls, tokens) — the test name `usage_matches_budget_charged`
  is read as "the usage matches what the run was charged by the server",
  verified against the journal's own records.
- `wall_ms` spans the whole journal (first to last record), including setup
  and the stop itself; it is display only.
- The footer reads only inline `claimed_stats` (small by construction);
  a blob-carried claim would show nothing rather than read the blob store.
- `--follow` never times out: it tails until the run commits or the journal
  ends unreadable (tail semantics, as with `tail -f`).
