# P-20 — Scripted scenario suite

## What was built

A new integration-test file, `crates/harness-run/tests/scenarios.rs`, with
twelve whole-session scenarios (`scenario_01_` … `scenario_12_`) run
through the public `run_session` (scenario 10 additionally through
`resume_session`) against a `harness-testkit` `Fixture`: real state root,
workspace and journal, real tools, `ScriptedBackend` and a scripted
`UserInput`. Every test asserts the final workspace files, the journal's
records (kinds, turn reasons, step counts, record bodies) and a clean
session audit. Tests only; no production behaviour changed.

## The scenarios

1. **Fix a failing test** (macOS-gated): read → `edit.replace` → run an
   allowlisted fake `cargo` (a `#!/usr/bin/perl` script under the
   fixture's base, outside the workspace, pinned by canonical path) that
   passes only after the fix → submit; the exec result carries
   `exited/0/confirmed`.
2. **Add a function**: read → `edit.write` → submit.
3. **Rename across files**: read both → `edit.multi` on each → submit.
4. **Refuse an out-of-workspace edit, then recover**: `edit.write` of
   `../escape.txt` is denied by policy (`path_outside_workspace`, no
   `ToolStarted`, nothing written), the turn continues and an
   in-workspace edit succeeds.
5. **Stale-read recovery**: the file changes outside the harness between
   turns (`external_change: true` on turn 2), the stale replace fails
   with `ToolFinished{status:error, code:STALE_READ}`, a re-read clears
   it and the retry applies.
6. **Loop detector**: repeated identical reads end the turn
   `loop:repeat` with `LoopDetected{kind:repeat, stop:true}`; the
   session continues with the next message.
7. **Budget notice then submit**: a 3-step turn allowance writes exactly
   one `BudgetNotice{key:"last_step", used:2, limit:3}` and the
   submission still ends the turn `submitted`.
8. **Presubmit turn-back then pass** (macOS-gated): the check
   (`perl`, `NEEDS_FIXED`) fails the first submission
   (`PresubmitChecked{result:failed, accepted:false}`, the turned-back
   submit is a tool error whose output names the check), the repair
   (`edit.write fixed.txt`) passes the second round.
9. **Approval denied then alternative**: the default (ask) policy with a
   scripted approver — `No` on the replace, `Yes` on the write;
   `ApprovalDenied` + `ApprovalGranted`, one `EditApplied`.
10. **Resume after a kill between intent and result**: `crash_in` before
    step 2's `ToolFinished`; `resume_session` drops the incomplete step,
    re-runs it live with a re-fed reply, attempt 2 edits the file and
    audits clean (`assert_session_audit_clean_with(..., Some(2))`).
11. **Compaction**: a small-window profile (8192 · 0.6, same shape as
    `tests/stable_context.rs`) plus three ~16 KB reads compact within
    one turn (`ContextBuilt.compacted` false → true) and audit clean.
12. **Two-turn follow-up**: the exact session kind sequence (two
    `UserTurn`/`TurnEnded`, `InputEnded{eof}`, `RunStopped
    {session_ended}`), chain head present.

## Decisions

- **New testkit helper** `assert_session_audit_clean` (+
  `assert_session_audit_clean_with`): the session twin of
  `assert_audit_clean`. Sessions cannot use the batch helper (it is
  refused at the header's `mode`), and the session audit must be given
  the run's own limits (`format_errors = u32::MAX`, the meter never
  latches format errors in a session), the session config's turn limits
  (the header carries them), and the same policy/profile the run had.
  The `_with` variant takes policy, profile, config and attempt so the
  custom-config scenarios (7: turn allowance, 10: attempt 2, 11: custom
  profile) audit against what actually ran. The anchor is the report's
  chain head; divergence must be `None`, the stop recomputed, the head
  anchored.
- **macOS gating** follows `tests/exec.rs`/`tests/presubmit.rs`: the two
  scenarios that run real commands (1, 8) live in a
  `#[cfg(target_os = "macos")] mod live` with the `Counting`
  (`SystemConfinement`) confinement, one live-probed witness per test
  binary. Scenario 1's fake test runner is a perl script (no
  subprocesses inside the sandbox), pinned by canonical path with the
  tools directory as a read-only root.
- **Scenario 6 scripts six identical reads**, not three: the detector's
  notice-vs-stop bookkeeping around repeated reads is not re-derived
  here; six identical reads trip the stop under either reading, and the
  test asserts the observed stop (`LoopDetected{stop:true}` +
  `TurnEnded{loop:repeat}`).
- **Resume shape in scenario 10**: the incomplete last step's records
  are not re-fed (the P-17 rule: records with `step < last` survive an
  incomplete last step), so the resumed backend is given the replace
  reply again, then the answer; `res.turns == 1`.
- Shared scaffolding (scripted input, approver, drivers, record
  readers) mirrors `tests/session.rs`; the file re-allows the panic-set
  lints at the top like every test file. `harness-testkit` stays inside
  the ratchet: both helpers return `Result<(), String>`.
