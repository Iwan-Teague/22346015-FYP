# P-36i — the background tools: `harness.exec.start/read/stop`

Implements the tool half of `docs/slices/P-36-background-processes.md`
(§3.1–§3.4, §5.2's facts, §6.2's connect list, §7.5's confined-helper
rule). Deps: P-36b/f/g/h (all merged). Crates: `harness-tools` (new
`bg/mod.rs`, `exec.rs` connect field, `file_ops` confined check),
`harness-run`/`harness-mcp` (record plumbing only). No new dependencies.

## harness-tools (`bg/mod.rs`, new)

- `BgManager`: the run's map of live processes (`Arc<Mutex<..>>`,
  cloneable so the runner and the future poller share it). Ids from 1;
  `BG_MAX_LIVE = 4` running at once, `BG_MAX_STARTS = 16` per run
  (stopping frees a live slot but never an id). An id is spent only
  when a start reaches the sandbox (a running start, or an
  `exec_failed` one that has a record carrying the id); every call-time
  refusal of §3.1 steps 1-6 spends nothing (design §11.2 recomputes ids
  from journal records, and a refusal leaves none). `live_ports()` is the
  sorted, deduped port list of running processes; `poll()`,
  `stop_all()` and `remove()` return `BgStopped` facts for P-36j's
  journal records (nothing is journaled here).
- `BgTools<'a>`: the `ToolProvider` for `harness.exec.start`, `.read`
  and `.stop`. Setup refuses unless `file_ops.is_confined()` (§7.5: the
  stop walk must not read the tree in-process while a started process
  may still write it) — `FileOps` gains `is_confined()` (default
  `false`), `Confined` overrides `true`.
- `start` (§3.1, refusal order verbatim): allowlist by name (INV-13
  defence in depth), cwd by the workspace rule, the live/starts caps
  (`BG_LIMIT`), ports in the task grant and not held by another live id
  (`BG_PORT`; a ready port must be one of the start's own ports, so the
  harness's readiness connect can never probe another service; a granted LAN port is recorded in the record's `lan` list
  — the ask itself was P-36g's), session scope only when the spec allows
  it (`BG_SESSION`), then the host bind probe (a `TcpListener` bind and
  immediate release; busy is `BG_PORT`). The spawn goes through
  `Confinement::spawn_live` with the run's witness,
  `LiveOpts { ring_bytes: BG_RING_BYTES (1 MiB), lifetime }`, network
  `Loopback { bind, connect: [], lan }` (and `Network::None` when the
  start names no ports), wall = the effective lifetime
  (ask, `BG_LIFETIME_MAX = 4 h`, never past the call's deadline). A
  sandbox refusal is recorded as `exec_failed`, not silence. The ready
  ask waits for a TCP connect or a text needle in either stream;
  not met is not an error. The result text starts
  `started background process N (program …, ports …, …)` plus a preview
  of the first output.
- `read` (§3.2): no id lists every known id (state, program, ports,
  scope, start step, undelivered byte counts). With an id the delivery
  cap (`BG_READ_MAX = 16 KiB`, default) splits 3/4 stdout, the rest plus
  stdout's unused share to stderr; the ring's `window` arithmetic does
  the cursor math, `[N bytes dropped]`/`[N bytes skipped]` markers and
  lossy UTF-8 included. `wait_secs` (≤ `BG_READ_WAIT_MAX = 30`) polls
  until new bytes or the end. An unknown or already-stopped id refuses
  with `BG_UNKNOWN`, repeating the recorded end.
- `stop` (§3.3): refuses for an already-ended id (deterministic repeat
  of the recorded end and the final totals), except that a process which
  ended on its own with an UNCONFIRMED sweep and still has its child is
  stopped again so the confirmation is retried (`stop_all` does the same).
  Otherwise closes the domain and reports the end (the sandbox reports an
  explicit stop it did not time itself as `Unknown`; the harness asked
  for it, so with a confirmed sweep that is the journal's `stopped`
  end), the cleanup, the output not yet delivered, and the workspace
  digest walked THROUGH THE HELPER. Fail closed: an unconfirmed sweep
  skips the walk and returns a non-Ok result (`Crashed`) whose record
  carries `cleanup: Unconfirmed` for the run to treat as a sandbox loss
  (P-36j); a failed walk returns an `IO` error result with the stop
  record attached (`BgStop.workspace = None`). The same record field
  carries the digest otherwise.
- After a stop the child is consumed, so the process's bytes can no
  longer be read: it stays in the listing as `stopped` (nothing pending),
  a read or a second stop refuses repeating the end and the FINAL stream
  totals, and `BgStopped` (from `poll`/`stop_all`/`remove`) carries the
  stream totals and digests for P-36j's `BgStopped` record. A process
  that ended on its own and was merely polled keeps its child and stays
  fully readable.

## harness-tools (`exec.rs`, `provider.rs`)

- `ExecRecord` gains `connect: Vec<u16>`: the runner computes
  `BgManager::live_ports()` before its spawn and, when non-empty, hands
  the sandbox `Network::Loopback { bind: [], connect, lan: [] }` (§6.2).
  Empty stays `Network::None`, so the journal field is written only when
  non-empty — every pre-P-36h body is byte-identical (P-36h's equality
  test now drives both shapes).
- `ToolResult` gains `bg: Option<BgRecord>`; the provider-level record
  types mirror the journal shapes of P-36h (the `ExecRecord` precedent:
  the tools produce, the driver converts at journal time). Every other
  provider's construction site carries `bg: None`.

## harness-run / harness-mcp

- `driver/step.rs` and `presubmit.rs` now write
  `exec_fields(x, &x.connect)`. `parse_exec` reads `connect` back into
  the record. The replay feed still writes no `bg` record — that
  re-feeding arrives with P-36k (comment at the construction site).

## Deviations (each small, all noted for the audit)

- The lifetime reason is the manager's clock (`started + lifetime`):
  `ConfinedExit` carries no closer flag, so `by_lifetime` is
  `TimedOut && elapsed >= lifetime` in `poll()`.
- `stop` reads the ring before `child.stop()` (the stop consumes the
  child), so bytes flushed during the sweep grace are not in the stop
  windows; the record's `out_total`/`err_total` and digests are taken
  just before the stop, so they also exclude bytes written during the
  grace (the window `total` is the same instant's count, §11.2's
  "BgStopped totals >= every earlier window total" holds).
- The reads' windows and totals are fetched by separate sandbox calls;
  `read` repeats the pair (up to 8 times) until the totals agree, so a
  window is never reported against a later total. A stream that never
  stops growing reports the later total.
- The start preview uses a tail read from 0 and advances the cursors:
  the preview counts as delivered (§3.1's "first output (tail mode)").
- `Proc` keeps no `lan` field: the lan list lives in the `BgSpec` and
  the start record only (nothing reads it off the process).
- Linux has no `spawn_live` implementation: the default trait refusal
  fails a start closed as `exec_failed` (D8), exactly as designed.

## Manifest (`harness-manifest`, one deviation from the earlier fragment)

`harness.exec.read`'s fragment (P-36g) declared `mode` as `out|err|both`
and required `id`, which contradicts design §3.2 (`next|tail`; no `id`
lists) and the tool. Through the real policy seam the tool could not be
called with `next`/`tail` or without an id (found by the live tests).
The fragment now matches the design; `builtin_manifest_bytes_unchanged`
is re-pinned (`bccdee9e...`), the third deliberate change after P-36g and
P-28 (journals from earlier builds are refused by name, as before).

## Tests

- `src/bg/tests.rs` (macOS, `cfg(test)`): 19 tests over a scripted child
  behind the crate-private `LiveChild` seam (the real `Ring`, real policy,
  journal, confined helper and host probes; scripted: output, exits, the
  sweep answer). Needed because the macOS conformance row has no
  `PORTS_CASES`, so the real sandbox refuses every loopback port start,
  and `ConfinedChild`/`Conformed` cannot be minted outside the sandbox
  crate. The seam is not reachable from outside the crate. Covers:
  refused starts burn nothing (every call-time refusal), the live cap, the
  16-start cap, sandbox-refused starts spending an id with an
  `exec_failed` record, held/ungranted/busy ports, the network grant
  (`None` / bind / lan), LAN record, hand-computed next/tail/dropped/
  skipped arithmetic and the stdout->stderr share, wait on output and on
  exit, ready port (met/not met) and ready text, stop (end, cleanup,
  output, digests, workspace), unconfirmed sweep and failed walk failing
  closed, stop after a poll-noticed exit (confirmed: refuse; unconfirmed:
  retry), `stop_all` totals/listing/`remove`, the listing, and the exec
  runner's `connect` grant (captured spec).
- `tests/bg_tools.rs` (macOS, REAL sandbox and helper): twelve tests for
  everything the real sandbox allows on this host (no ports) and every
  refusal before the spawn: sequential ids, allowlist, ungranted and busy
  ports spend nothing, both caps (16 real sandboxes), hand-computed
  next/tail arithmetic, ring overrun (exact dropped count), wait,
  listing, unknown id, stop sweep (end, cleanup, output, digest,
  refusals after), the confined-file-ops setup rule. No real test names a
  port in a start that must spawn.
- Linux gates (earlier session runs, not repeated): see the history of
  this note; the macOS-gated suites above are NOT compiled on Linux.

## Review notes (F1, F3, F5)

- F1: `BgTools` carries `protected_dirs` (`with_protected_dirs`, as
  `ExecTools` does) and passes them into every start's `ConfinedSpec`, so
  background processes get the P-29 read-only overlays too. Test:
  `spawn_carries_the_protected_dirs`.
- F3: an explicit stop is journaled as `TimedOut` because `ExecEnd` has no
  `Stopped` variant. The P-36k audit must distinguish an explicit stop from
  a real timeout by `by_lifetime`.
- F5: design section 11.2 "attempts continue the count" is read as:
  `exec_failed` attempts spend an id; refused call-time starts do not.
- While a background process holds a port, every `exec.run` needs the host's
  loopback-connect conformance row (it fails closed otherwise).

## Not in this slice (and why)

- Journaling `BgStopped` at step boundaries and the turn-end
  `stop_all`: P-36j (the driver). `BgManager::poll/stop_all/remove`
  return the facts; nothing writes them yet.
- Replay re-feed of `bg` records: P-36k (`feed.rs` keeps the name
  refused, as P-36h left it).
