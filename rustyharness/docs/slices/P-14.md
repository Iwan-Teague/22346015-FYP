# P-14 — `sessions` list/show, run bundle, `gc`

Branch `w/P-14`. No new dependencies; `Cargo.lock` unchanged.

## What was built

- **`scan_runs`** (`crates/harness-journal/src/scan.rs`): read-only scanner over
  `<state_root>/runs/`. Returns one `ScannedRun` per directory whose name parses
  as a `RunId`; symlinks and non-run entries are skipped, never followed. For
  each run the latest attempt is opened with `JournalReader` (chain-verifying);
  a missing attempt or a failed open is reported as `ScanError::NoAttempt` /
  `ScanError::Read`, not skipped. `runs/` missing while the state root exists →
  empty list; state root missing → `NotFound`. The `runs/` directory being a
  symlink is refused. `canon::rfc3339_utc` is now re-exported from the crate
  root (it was already `pub`, just unlisted).

- **`sessions`** and **`sessions show --run <id>`** (`cmd_sessions.rs`): not
  gate children. Options: `--state-root`, `--run`. Lists runs newest-first by
  start wall time (`t_wall` is RFC3339 with fixed-width millis, so string
  compare is chronological; ties broken by run id; unknown start sorts last).
  One stdout line per run:
  `<id> <start> steps=<n> stop=<cause> outcome=<o> head=<hex> workspace=<w> task="…"`
  with `-` for anything unknown. A broken journal is listed as
  `<id> UNREADABLE (<reason>)`, never silently skipped. First user text comes
  only from the run bundle (`inputs/task.json`) — the journal stores just the
  task digest — sanitised with
  `sanitize_for_terminal_bounded(.., DisplayMode::Line, 60)`. `show` adds
  attempt/committed detail on stderr. Exit codes: 0 ok, 2 usage, 4 bad state
  root/config/unknown run, 5 scan failure.

- **Run bundle** (`bundle.rs`): after a successful `run`, the CLI copies the
  resolved inputs into `runs/<id>/inputs/` — `task.json`, `profile.json`,
  `policy.json` (exact original file bytes; `policy.json` only when a policy
  file was given) plus `bundle.json`
  `{format:"rh-bundle/1", endpoint, workspace, policy, task_sha256,
  profile_sha256, policy_sha256}`. Dir 0700, files 0600. Digests are computed
  exactly as the journal header does (task text sha256, profile
  `content_sha256`, `UserPolicy::digest` — the default policy's digest when no
  file was given). Writing is self-verifying: each copied file is re-parsed and
  its recomputed digest must match, and the latest attempt's header fields
  (`task`/`profile`/`policy`) are re-checked from the journal itself. Any
  mismatch → the bundle is removed and the CLI notes the failure and adds a Low
  finding (`harness.bundle`); the run outcome is kept (the run had already
  committed).

- **Bundle use** (`fill` in `bundle.rs`, called from `dispatch` before verb
  dispatch): when `--run` parses and `runs/<id>/inputs/bundle.json` exists,
  missing `--task`/`--profile`/`--policy` (and, for `run`/`resume`,
  `--endpoint`/`--workspace`) are filled from the bundle; flags and user config
  always win. The effective inputs are then re-digested and compared against
  the bundle's recorded digests — a mismatch is `refused(UNREADABLE_INPUT)`
  (exit 4). When flags are given explicitly they override the bundle files, and
  the digest check still applies (so a wrong flag is refused here too, before
  the audit's second line of defence). Runs without a bundle (older runs)
  behave exactly as before: flags required.

- **`gc`** (`cmd_gc.rs`): not a gate child. Options: `--state-root`, exactly one
  of `--run <id>` / `--older-than <N>d` (`N > 0`). A run is only ever cleaned
  when its latest attempt journal verifies AND is complete (last record
  `RunStopped`, no torn tail) — an unreadable or uncommitted journal is treated
  as possibly-active and refused, never cleaned. Removal is limited to plain
  (non-symlink) directories `workspace/`, `grading/`, `scratch/` under the run
  directory; absent ones are skipped (idempotent). Journals, `blobs/`,
  snapshots, `replay-*/`, and `inputs/` are never touched. `--run` refusal →
  exit 1; `--older-than` sweeps all runs older than the cutoff (start `t_wall`
  compared lexicographically against `now - N days`), skips-and-reports the
  refused ones, and exits 0 with a summary.

- **USAGE** gained the `sessions`/`gc` lines and a bundle paragraph; the
  `usage_text_unchanged` golden was updated deliberately.

## Not done here (by design)

- `chat` does not exist yet (P-18): only `run` writes a bundle; `resume`/`replay`
  only consume it.
- Workspace paths in `bundle.json` are recorded as given (the CLI resolves them
  itself on reuse); `sessions` shows the recorded string, no canonicalisation.
