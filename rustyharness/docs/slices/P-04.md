# P-04 — Terminal-safe display (`harness_core::display`)

## What landed

- `crates/harness-core/src/display.rs` — the one pure escaper every display
  path runs untrusted text through before printing:
  - `escape_for_terminal(&str, DisplayMode) -> String`: every control
    character (ESC, DEL, the C1 bytes — so the CSI/OSC introducers 0x9B/0x9D
    are covered), line/paragraph separator, and zero-width/bidi code point
    becomes the journal's `\u{HEX}` spelling (§7.1). Nothing is deleted: a
    CSI or OSC sequence is neutralised by escaping its introducer and its
    remaining bytes stay visible as inert text, which also handles a
    sequence truncated at a chunk boundary with no cross-call state.
  - `DisplayMode::Line` escapes raw `\n` as `\u{A}` (one-line fields:
    prompts, labels, approval requests); `DisplayMode::Block` keeps `\n`
    and `\t`. `\t` is kept in both.
  - `sanitize_for_terminal_bounded(s, mode, max)`: escape plus a hard bound;
    the returned string is at most `max` bytes and, when input was left
    out, ends with the visible marker `[N bytes cut]` (`N` = input bytes
    not represented). The marker is never dropped: with `max` smaller than
    the marker, the marker alone is returned.
  - `sanitize_for_terminal(s, mode)`: the same at
    `DISPLAY_MAX_BYTES = 8192`.
- `crates/harness-policy/src/approval.rs`: the §5.3 approval request now
  renders its arguments through `harness_core::display::escape_for_terminal`
  instead of `harness_manifest::display_safe` (its bound of
  `APPROVAL_ARGS_SHOWN` characters and its `… (N more characters not shown;
  sha256 of the call …)` line are unchanged — the sha256 line is
  load-bearing, so the bounded variant with its own marker is not used
  there).

## Idempotency and the backslash rule

The card requires the escaper to be idempotent (`f(f(x)) == f(x)` for every
input) **and** the approval rendering to keep its output. These constrain
the backslash: doubling every backslash (what `display_safe` does, to stay
reversible) is not idempotent — a doubled backslash doubles again. The rule
implemented:

- a `\` that opens an escape sequence this module itself produces (`\\`,
  `\u{HEX}` with uppercase hex) passes through untouched;
- every other lone `\` is doubled.

So the reversible spellings the journal and JSON write (`\n`, `\r`,
`\u001b`, `\\`) still double exactly as before (the existing
`h2b_the_approval_request_escapes_and_bounds_the_arguments` pins
`\\u001b`/`\\r`), and the escape is idempotent for every input, including
the bounded form (an output within its bound is a fixed point: the
whole-fit branch returns it unchanged).

Documented divergence from `display_safe`: input text that already *looks*
like `\\` or `\u{HEX}` (e.g. an args value containing a literal backslash,
written `\\` by JSON) passes through once instead of doubling again. The
golden test `approval_request_display_unchanged` pins a full request whose
escapes agree byte for byte under both escapers, and asserts that equality
explicitly. Owner question if this matters: none expected — both renderings
are equally terminal-safe; the new one shows one fewer doubling layer for
backslash-bearing arguments.

## Consumers

P-14 (`sessions`), P-15 (`events`), P-16 (diff preview) and P-18 (REPL)
print untrusted text; they should call `sanitize_for_terminal` (Line for
one-line fields, Block for output blocks) or the bounded variant for hard
caps. The context builder's own stripping (`harness-model-core::wire`) is
unchanged: it feeds the MODEL, this feeds the TERMINAL, and the two have
different contracts (strip-withhold vs escape-visibly).
